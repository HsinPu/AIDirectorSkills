# 官方解析度與畫面比例設定

文件查證日期：2026-09-30。以下為 OpenRouter 的欄位與官方參考快照，執行時仍查 `GET https://openrouter.ai/api/v1/videos/models` 中選定模型的能力。不能把全 API 的可接受值當成每個模型都支援。

## API 欄位

| 用途 | 請求欄位 | 先核對的模型欄位 |
|---|---|---|
| 解析度級別 | `resolution`，例如 `"720p"` | `supported_resolutions` |
| 寬高比例 | `aspect_ratio`，例如 `"16:9"` 或 `"9:16"` | `supported_aspect_ratios` |
| 精確寬×高 | `size`，例如 `"1280x720"` | `supported_sizes` |

比例使用寬:高；尺寸使用寬x高，`x` 是英文字母。API 字串不含空白：使用者輸入「16: 9」時正規化為 `"16:9"`。

現行提交 schema 列出的解析度值：`360p`、`480p`、`720p`、`768p`、`1080p`、`1K`、`2K`、`4K`。比例值：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`3:2`、`2:3`、`21:9`、`9:21`。這是 API 全域列舉；只將所選模型確實支援的值提供給使用者。

一般使用 `resolution` 加 `aspect_ratio`；要精確像素時改用模型支援的 `size`。不要同時送兩套可能矛盾的表示方式。比例與解析度寫入請求欄位，不能只寫在自然語言提示詞中。紀錄使用者指定或委託的選擇，下載後可讀取媒體資訊時核對實際尺寸，不只核對提交值。

## 最低解析度與實際片長

使用者要求最低解析度時，選所選模型當下最低支援值，不跨模型沿用範例規格。已授權「最低可用」不重問同一選擇；指定的精確值不受支援時，說明可用替代選項並詢問。

交付時核對請求片長與媒體實際時長，記錄差異；需要精確剪輯接點時，依已授權剪輯範圍處理，未授權時先說明影響並詢問，不自行裁掉對白或已接受的尾段。

## Seedance 2.5 參考快照

模型 ID：`bytedance/seedance-2.5`。OpenRouter 官方文章於 2026-09-03 查詢模型 API 所記載：解析度為 `480p`、`720p`，比例為 `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`。這份表是文章的歷史快照，不是本次直接呼叫模型 API 的結果，也不能沿用 Seedance 2.0 的 1080p／4K 規格。

| 比例 | 畫面形狀 | 480p 尺寸 | 720p 尺寸 |
|---|---|---|---|
| `16:9` | 橫式寬螢幕 | `854x480` | `1280x720` |
| `9:16` | 直式 | `480x854` | `720x1280` |
| `1:1` | 正方形 | `640x640` | `960x960` |
| `4:3` | 橫式 | `752x560` | `1112x834` |
| `3:4` | 直式 | `560x752` | `834x1112` |
| `21:9` | 超寬橫式 | `992x432` | `1470x630` |

以上是官方列出的離散尺寸，部分與名義比例有像素取整差異；不要自行計算另一組像素後假設 API 可接受。直式 `720p` 不等於寬度一定是 1280；以模型列出的 `720x1280` 等實際尺寸為準。

## 使用者未指定時

1. 先讀目前專案與對話中已確認的設定；沒有設定才查詢。若已指定模型，先取得該模型能力；模型尚未選定時先找候選模型的可用規格，不假定某一模型的規格適用全部。
2. 查模型 API 與必要的官方供應商規則，只呈現可用選項。快照過期或規格改變時，依現行規則更新請求與參考紀錄。
3. 將缺少的兩項合併成一個簡短問題，明確列出解析度與比例，附符合用途的建議。例：「這個模型支援 480p／720p，以及 16:9 橫式、9:16 直式等比例；這次要用哪個解析度與比例？一般橫式影片我建議 720p、16:9；直式影片則建議 720p、9:16。」這句僅在即時模型確認支援時使用。
4. 等使用者回答；沒有回答不算授權代選。繼續準備不依賴輸出規格的工作，保留待選狀態。使用者明確說「你決定」時才代選，說明畫面用途及成本取捨並保存設定。

已指定精確尺寸、已確認的專案設定或已明確委託決定，不新增同一個確認關卡。只有來源素材的比例不代表使用者已選定輸出比例。

首尾幀、影片編輯或延長模式可能有跟隨素材比例的限制；先核對所選模型與 OpenRouter 映射。供應商的 `ratio: adaptive` 不在 OpenRouter 全域 `aspect_ratio` 列舉中，不能直接混用；若無法表達需求，先解決介面限制再生成。裁切、補邊或後製升頻是另一項製作決定，不用它們掩蓋模型未支援的輸出規格。
