# 成片起始畫面與參考素材上限

新製作範圍一律準備成片風格的起始畫面資產。全片第一鏡必須有；每個單獨生成的鏡頭／片段都要有自己的局部 0 秒畫面。多鏡合併成一次生成時，以該單元第一鏡的起始圖作為開場來源，其他鏡的起始圖保留在各鏡素材包並按需要引用。已核准的舊套件不因 Skill 更新自動補圖、重畫或重送；使用者要求升級時，只處理缺口。

## 圖片要表達什麼

起始圖是一張獨立、完整畫幅的成片畫面，包含該鏡開場的主體、姿態、道具狀態、環境、景別、機位、構圖、光線、色彩與最終媒介。比例依已確認成片設定，不帶漫畫格線、運鏡箭頭、說明文字或 Blender 除錯標示。

若劇本要求遊戲畫面，就畫出約定的遊戲渲染、視角與必要 HUD，例如小地圖、任務標示；只有已採用的元素才加入。其他題材沿用各自風格，不一律加 45 度機位或 GTA 介面。HUD 是創作內容；漫畫頁註解及軟體除錯資訊是輔助標示，不能一概排除。

| 來源角色 | 提供的資訊 | 不取代的來源 |
|---|---|---|
| `start_frame_visual_reference` 起始畫面 | 局部 0 秒的構圖、環境、成片風格及約定介面 | 完整動作／運鏡參考與已選定人物參考圖 |
| `storyboard_sequence_page` 完整六格頁，或預演影片 | 動作先後、走位、機位與攝影意圖 | 成片美術與臉部身分 |
| `character_appearance` 已選定人物參考圖（設定圖或原照） | 人物臉部、髮型、體態與服裝 | 起始構圖與後續運鏡 |

起始圖中的人物仍須依[已選定的人物身分來源](character-image-assets.md#人物參考的選用與交付)繪製；起始圖中的臉不能反過來替換該設定圖或原照。沒有角色的作品只記錄身分規則不適用，不增加人物。

## 製作、審閱與交付

1. 劇本與分鏡表確認後，從各鏡開場狀態規劃起始圖與參考配額。先找適用的既有已核准圖，缺少時才依授權範圍製作；不要為整理交付重畫運鏡頁。
2. A 路線與整批六格分鏡及外觀素材一起製作、展示與審閱；B、C 與圖片素材批次一起準備，靜態／動畫仍依原本階段辦理。不新增逐鏡起始圖確認點；同批確認保存各圖的版本及適用範圍。
3. 原檔放在影片專案內，例如 `assets/start-frames/SH01-start-v001.png`，複製到各鏡 `delivery/<revision>/SH01/media/`。生成單元另有自身 `media/` 和完整提示詞；所有實際提交來源在該包內可找到。
4. 素材清單保存穩定 ID、角色、鏡頭／單元、來源路徑、採用版本、交付路徑、大小、SHA-256、來源照片／提示詞、確認證據及 `input_to_video_ai: true`。專案狀態另追蹤 `start_frame_image_status`，不要把寫好提示詞當成圖已完成。
5. 提示詞與來源對照表分別說明起始圖、完整運鏡頁／影片與已選定人物參考圖的用途，沿用有效的標籤順序；新增圖片不任意重排既有標籤。複製後比對大小與雜湊，缺圖、漏列輸入或模式未解決時不得宣稱可直接提交。

起始畫面是素材用途，**不自動等於 API 原生首幀**。先查所選模型與實際介面：一般參考模式把起始圖與其他必要來源一同提交；原生首幀模式才使用 `first_frame`。OpenRouter 的 `frame_images` 會優先於 `input_references`，不可假設同時填兩欄就保留全部參考。模式限制需要改動已確認的來源策略時，說明影響、依既有授權解決；完整原頁及人物來源仍保留，不能靜默丟棄。API 接受素材不證明精確首幀、身分或全部六格已生效。

同一動作接續生成時，起始參考可沿用上一段實際採用範圍的最後有效影格。圖片階段先依既有確認／委託記錄尾格接續策略與預計開場；實際尾格待前段生成並確定採用範圍後才取得，未取得前標記待補。選格後保存來源影片／工作、版本、影格時間及雜湊，並同步下一單元的起始圖、素材清單及提交內容。改機位或換場時依接點狀態設計相容的新開場，不強迫複製舊構圖。具體選格、同步欄位、偏差處理及適用限制見[鏡頭時長與連續性](shot-pacing-and-continuity.md)。

## 數量與分配

每鏡已採用的媒體清單，以及每次實際提交，都須符合下列製作上限；未採用草稿與歷史來源留在製作區，不混進採用的 `media/`。

| 類型 | 上限 | 計數方式 |
|---|---:|---|
| 圖片 | 9 | 起始圖、完整運鏡頁、人物、場景、道具、原生首／尾幀都計入；一張完整六格頁算 1 張 |
| 影片參考 | 3 | 每個實際提交的影片檔／輸入項目算 1 段 |
| 聲音參考 | 3 | 每個上傳聲音檔／輸入項目算 1 段；對白文字與 `generate_audio` 的輸出不計入 |

以較嚴格的模型／供應商／模式限制為準，並保存查證來源與日期。H3／H3 Max 另保守套用全部參考合計最多 12 個，不能把 9＋3＋3 當成可同時送 15 個；影片／聲音時長、格式與實際路由支援仍須另查。此製作配額不是所有模型支援多素材的承諾。

合併多鏡時重新計算單次請求的全部輸入，不能逐鏡重置配額。共同人物圖只實際送一次就算一次；重複送入同一檔仍占輸入數量，不以雜湊去重來放寬上限。先分配起始圖、必要完整運鏡頁／預演及人物身分來源，再安排場景、道具與聲音。超額時查找可共用的相同來源，或依模型時長、節拍與既有授權調整單元；不要自行刪除已核准的必要來源、合成人物拼貼、拆格、改故事或增加付費提交。需要使用者決定的創作／生成範圍變更才提出問題，單純檔案整理不增加審閱。

## 可檢查的交接欄位

新 `generation-package.json` 使用 `asset_contract: "start_frame_v1"`，每個 `generation_units[]` 指定 `start_frame_reference_id` 並列入自身 `reference_ids`；該來源必須是 `kind: "image"`、`role: "start_frame_visual_reference"`、`input_to_video_ai: true` 的真實非空圖片。可選的 `shots[]` 用 `shot_id`、`reference_ids`、`start_frame_reference_id` 宣告各鏡素材，讓檢查器也核對每鏡配額。新逐鏡 manifest 同樣保存上述欄位，不只在文字提到起始圖。

套件、鏡頭及單元可保存已查證的 `reference_limits`，例如 `{"image": 6, "video": 2, "audio": 0, "total": 8}`；非負整數，0 表示不允許該類型。有效上限取製作配額與宣告限制的較小值，不能藉欄位放寬 9／3／3；H3 的總上限也不能放寬。`model` 填入確切模型 ID，未知時保留未知並在提交前查證。

[離線交接檢查](offline-handoff-check.md) 可核對已宣告數量、起始圖是否存在及是否列為輸入，不能辨識畫面風格或證明實際 API 綁定。未宣告新合約的舊包保持相容，不被追溯要求補圖；新製作不可省略合約來跳過起始圖要求。
