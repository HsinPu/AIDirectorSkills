# 依鏡頭需求加入的簡化手部 IK

這項選用的接觸附件屬於圓柱／球形／四骨骼結構代理，用來表達哪隻手碰觸什麼、誰持有道具，以及何時操作或放手；它不是全身表演。

## 依鏡頭決定是否需要

駕駛、穩定持物、遞交、按壓或開啟若可見且攸關故事，使用 `contact_ik`。手部出畫、確實被遮住、太小，或主體／道具運動已能交代關係時，就不使用。奔跑、打鬥、快速出擊與撲向目標，預設不加手部，只呈現根節點移動、朝向、彎曲、道具事件與結果。連續鏡頭若從穩定接觸轉入動作，要完成放手或交接；已入鏡的簡易附件仍須保持連接，不需加入激烈擺臂，也不能突然消失。

分鏡階段記錄鏡號、以角色自身為準的左／右手、目標道具、接觸時段與理由。高速行駛的車仍可能需要穩定的駕駛接觸；「邊跑邊持物」不代表要動畫化擺臂。明確要求無手或細緻四肢時，僅在指定範圍內覆蓋預設。要求局部可見四肢，不等於建立永久性的全身手臂。

## 最少幾何與比例

保留原本圓柱與球體。每個需要的側邊只加低面數上臂、前臂與掌塊，最多三個可見網格，不做漂浮手掌。左右可共用網格資料。不加肩／肘球、手指、指甲、皮膚或服裝細節；使用角色代理顏色。

起始比例：在角色局部座標中，肩部連接位置的 x 約為 ±W/2、z 為 0.93L；上臂 0.17H、前臂 0.15H、手臂直徑 0.05H、掌塊長／寬／厚為 0.075H／0.055H／0.025H。依既定體型調整。左右手依角色自身座標命名，不依畫面左右。

附件連到會變形的上半身。設定 IK 前先處理人、座椅與道具位置及可及範圍。坐姿鏡頭要確認骨盆、座面、椅背、支撐、軀幹方向與接觸表面。手腕端點、掌面與握點不同；端點靠近目標，手腕仍可能反折。不能為了接觸而拉長四肢、縮放身體，或移動已確定位置的方向盤。

## 骨架與控制權

1. 每個需要的側邊，在同一 Armature 中加入 `UpperArm`、`Forearm` 與 `Hand`。肩部以偏移量連到 `TorsoUpper`，連接前臂，掌塊綁到 `Hand`。根節點位移只繼承一次。
2. 前臂使用手腕 IK 目標，chain length 設為二並關閉拉伸。穩定的 pole target 決定肘部方向；起始略為彎曲，避免直線奇異姿勢。掌面朝向另行控制，手腕與掌面接觸點保留偏移。
3. 骨骼、IK 目標、pole 與握持錨點都不算入成片。pole 保持在穩定的身體／載具座標中；目標的控制者跟隨預定接觸物件。
4. 每個時段為道具與手指定單一控制來源。駕駛時由方向盤上的控制點帶動握持錨點，雙手跟隨；持物時由一個握持控制點帶動手部目標與道具偏移。遞交或放手時在實際接觸點切換，保留世界座標變換。絕不可一面把道具設為手的子物件，一面把手的 IK 目標設為道具的子物件，造成循環相依。
5. 優先移動或交接目標，不必建立完整 IK／FK 切換系統。確實需要切換時，在切換影格對齊世界座標姿勢與方向；只改影響權重可能造成跳動。

依實際 Blender 版本檢查 RNA 對 IK chain、pole 與 stretch 設定的支援。上述尺寸與範圍是本製作的選擇。

靜態階段建立並綁定附件，但不做動畫，完成後展示。若在先前靜態確認後才加入，只展示受影響的靜態變更；同範圍已確認者不重複。動畫化接近、接觸、持續握持／操作或受阻、放手、離開及結果。不加手指動作、花式表演、待機揮手或呼吸晃動。先安排人與物件並確認淨空，再調整手腕與掌塊；端點正確不代表整隻手臂都不會碰障礙。

SceneSpec 或相關紀錄中的選用 `contact_hand_plan` 可保存 `character_id`、`shot_ids`、`mode`、`sides`、`purpose`、`target_ref`、`phase_range`、`control_owner`、`continuity`、`dimensions_ref` 與 `status`。規劃範例不等於已建立或已驗證。分鏡、控制項與提示詞中的手／道具關係須一致。

製作期間檢查受影響的入場、轉身、窄道、接觸、交接與離場影格：左右手分配、肩部連接、可及性、肘部翻轉、手臂／掌塊體積、循環相依及世界座標跳變。有限取樣不能證明每一格都有淨空。快速驗證器不驗證手部 IK、掌面接觸或交接；未知事項維持未知。動畫確認後不新增 AI 複核。

對實際的 `@videoN` 參考素材，說明簡化手部只提供接觸位置、持有關係及操作／放手時機。排除棒狀手臂、方塊手掌、僵硬握姿與未規劃的擺動。最終影片的表演補足自然手指、握持、力量與手臂動作。若沒有做手部動畫，不可聲稱參考影片包含手部軌跡；以文字描述奔跑／打鬥時自然的手臂動作。
