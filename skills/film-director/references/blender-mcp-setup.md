# Blender MCP 連線與安裝選項

本頁只處理 AI 用戶端與 Blender 執行個體之間的 Blender MCP 連線。選用靜態模型生成服務時，另依[Hyper3D 分支](hyper3d-scene-assets.md)確認 Hyper3D MCP；兩種連線不能互相代替。

## 何時檢查

只在實際開始 Blender 製作、修訂、約定的匯出之前，或使用者要求安裝／診斷時檢查 Blender 連線。訪談、劇本、分鏡與圖片準備不依賴 MCP。動畫確認後若只交付提示詞，不因此觸發連線測試。同一主機、工作階段與目標執行個體的連線未變時，可沿用有效的檢查結果。

先發現工具及其實際參數。若工具允許，做一次輕量的唯讀呼叫，辨識目標 Blender 版本、檔案路徑與場景。不要只為測試連線就建立物件、切換影格、擷取圖片、算圖或掃描場景。工具出現在清單、連接埠開啟或安裝指令成功，都不能單獨證明已連到預期執行個體。

只診斷失敗的層次：缺少 MCP server／相依套件、用戶端註冊尚未載入、Blender／附加元件／服務未啟動，或版本、位址、執行個體不符。狀態未知就是「尚未確認」，不能說「尚未安裝」。有多個 Blender 執行個體時，寫入前先辨識目標。可沿用已正常運作的 MCP 實作，不強迫換成特定品牌。

## 元件缺失時

說明具體缺口，並在一般對話中提供兩個選擇：

1. 「告訴我如何安裝或啟用」：依實際作業系統、Blender 版本與 AI 用戶端提供步驟。
2. 「幫我安裝與設定」：完成已授權的缺失元件與最低限度連線檢查，指出最後仍須手動啟用或重新載入的步驟。

不要使用系統選擇卡。只有使用者選擇第二項或先前已授權，才安裝或修改設定；既有選擇可沿用。單說「開始製作」不等於授權安裝新軟體。若只是尚未啟用，說明啟用／連線方式，不重新安裝。

引導使用者自行安裝時，引用官方來源，提供實際路徑／指令、啟用位置與成功判斷方式。只詢問會改變指令的缺失資訊。使用者完成步驟後，接續最低限度的唯讀連線檢查與已核准的製作工作。

由助理安裝時，使用可呼叫的用戶端工具或官方手動設定方式。依實際主機、Blender 與用戶端，從官方來源選擇相容版本。執行時相依套件留在可發布 Skill 外，最好安裝在使用者層級並隔離。分別處理 server、Blender 附加元件與用戶端註冊。備份受影響設定，只修改目標項目。不可默默更換 Blender 主要版本、購買服務、下載無關大型套件或變更全域核准政策。

依該實作真正使用的傳輸方式、位址、連接埠、附加元件 ID、啟動指令與用戶端格式設定；不同實作不可任意互換。可自動完成的步驟應完成。最後若須使用者點擊、授權或重新載入，清楚說明，不重複索取安裝許可。分小批依序執行，不強制關閉使用中的程式、反覆重裝或繞過工具權限。若無本機執行能力，只回報準備好的指引，不宣稱已安裝。

## 已記錄的範例與完成條件

截至 2026-09-10 的查核，Blender Lab MCP 由 Blender 附加元件、server 與支援 MCP 的用戶端組成。當時的 v1.0.0 server 需要 Python 3.10+，提供 `blender-mcp` 與 `python -m blmcp` 入口。`.mcpb` 套件僅適用於支援該格式的用戶端。Codex 可用 `codex mcp add <name> -- <command> ...` 或目前有效的 `config.toml` 中 `mcp_servers` 項目註冊本機 server。安裝時應重新核對官方版本、路徑及指令；這些只是範例，不是鎖定的相依版本。

設定後重新發現工具，重做最低限度的唯讀查詢。若仍待重新載入，說明「已設定，待載入及確認連線」。只有收到目標 Blender 的有效回應，才說「已連線」。接著依[Blender MCP 執行規範](blender-mcp-execution.md)繼續，不新增創作確認或算圖。連線成功只能證明可存取，不能證明模型或動畫品質。
