# 專案紀錄與持續製作

每部影片、廣告或系列作品都維護獨立專案。已安裝技能只保存規則；不要把使用者素材或 Blender 檔案放進技能資料夾，也不要掃描無關的磁碟位置。

## 自動決定專案位置

寫入專案檔案前，依下列順序決定位置，不要求使用者選資料夾：

1. 沿用使用者明確指定的路徑、已辨識的既有專案，或此工作階段唯一綁定的專案。新的使用者指示優先於舊綁定。
2. 若可寫入的工作區根目錄同時有 PROJECT.md 和 project-state.json，就視為專案根目錄並檢查。名稱相似或最近修改，不足以確認身分。
3. 使用者說「繼續」但工作階段未綁定時，只檢查 director-projects/ 下第一層專案入口。沿用名稱或 project_id 唯一符合的專案，或唯一既有專案。若多個專案都可能符合，詢問要繼續哪一部作品；這是在確認身分，不是要求選資料夾。
4. 其他情況，在目前可寫入的工作區建立 director-projects/<safe-project-id>/，依片名產生簡短且安全的 ID。尚無片名但需求清楚時，使用 film-YYYYMMDD-HHMMSS；撞名則加數字尾碼。不可覆寫舊專案。若目前目錄是已安裝技能，改用任務的可寫入工作區。沒有可寫入工作區時，先在對話中推進，並說明檔案障礙。

首次寫入時記錄路徑及 project_root_source（user_specified、session_bound、workspace_project 或 auto_workspace），並告知使用者實際路徑。維護技能本身不會建立影片專案。

## 脈絡與入口

每次啟動時辨識 project_id、名稱、路徑，以及「繼續」「下一場」「分支」等語句。閱讀 PROJECT.md、project-state.json、已建立索引的單集進度、相關設定與最後交接。若明確指定的資料夾缺少入口檔，僅在該資料夾內依檔名尋找既有劇本、分鏡、設定、素材清單與交接筆記，再建立最小索引；不要說它是空專案，也不要掃描整個磁碟。

範圍不明時，提供三項有紀錄依據的方向並允許自由回答，不能為了湊選項編造未寫出的場景。接續時說明沿用的事實、已寫內容、已製作內容及下一個已授權步驟。專案資料留在專案內，不放進全域素材庫。

PROJECT.md 是人員入口；project-state.json 是機器可讀的目前狀態。索引目前劇本、分鏡、影片語言、場景計畫、素材、Blender 檔案、參考影片、提示詞、修訂、核准證據及下一檢查點。建議的資料夾配置可自行調整，檔案只在工作需要時建立。段落完成與整個專案完成是不同狀態。

## 設定、偏好與目前事實

以穩定 ID 加姓名或固定稱謂記錄角色，並保存別名、關係、外觀、聲線、所知資訊、動機與目前狀態。記錄世界、地點、物件歸屬、既定事件、觀眾所知、未解伏筆與結尾狀態。提議中的結局不算既定設定。類型、主題、暴力和情緒尺度、視角、節奏、不可更動事件及結局偏好，都要標明專案／單集／鏡頭範圍。

screen-language.md 保存已採納的媒介、視角、景別、構圖與軸線、鏡頭長度原則、手持幅度與適用區間、色盤、飽和度、對比、光源、質感、聲音、預演用途及例外。長期風格可跨全片適用；單一場景的快慢節奏則不會。

每項事實與決策都記錄來源、修訂、範圍及狀態：confirmed、delegated、proposed、inferred、superseded 或 retconned。優先順序是使用者目前明確指示、已確認的現行專案內容、明確委託的長期偏好，最後才是技能預設值。

依[互動式開發](interactive-development.md)記錄問題 ID、原始選項、傳遞方式、回答與未決項目。檔案存在不等於已作答或已閱讀。每個工作階段重新檢視暫時性的對話限制，不捏造舊答案。

製作關鍵事實須各有一個目前採納值：身分、空間、物件持有、接觸、方向、動作起訖與時間基準。project-state.json 指向目前來源；PROJECT.md 應與設定一致。歷史快照保留當時認知，標為歷史，不與目前來源競爭。舊檔若仍有連結，要指出新來源取代哪些欄位。不能讓舊劇本標成「目前版本」，卻只在新提示詞中推翻其中事實。

新決定出現後，同步所有受影響的目前設定、鏡頭、事件、提示詞與接續入口。原始訪談回答保留，但標明歷史狀態。核准要對應實際成果、版本、範圍與時間。使用者對成果的回報不等於助理親眼觀察；整體核准也不代表每項技術測試都通過。

## 場景節奏約定

節奏屬於段落、場景、節拍與鏡頭，不只由專案語氣決定。sequence-map.md 描述較大的能量與資訊變化。每份場景計畫有自己的 pacing_profile，包含敘事目的、資訊速度、表演能量、攝影機能量、剪接密度、聲音節奏及必要的理解或反應時間窗。理由應來自故事因果，而非只有數字或「快／慢」。

    pacing_profile:
      mode: conversational_tension
      information_rate: measured
      performance_energy: restrained
      camera_energy: low
      editorial_density: sparse
      required_readability: [reaction_before_cut]

分配動作、必要資訊辨識及結果後停頓的時間。區分快速動作與較短的收束。在固定總時長下，說明增加的時間從哪裡取得、節省時間如何運用；不自動挪到同一鏡頭末端。縮短整場戲時，應重新設計事件與鏡頭，同時保留因果及反應時間窗。各層次可自然重疊。

鏡頭要連結節拍，記錄影格範圍、剪接理由及 pacing_intent。對白可能在克制的機位下維持高度資訊張力；動作角色可有能量，空間鏡頭則仍需穩定可讀。調整節奏時，同步受影響的節拍時間、ShotSpec、角色和道具事件、曲線、攝影機路徑及標記、附著可見性、結束狀態、連續性、軌跡與提示詞。不要只把舊動畫整體縮放時間。已核准提示詞的交接，不會只因新增此約定就追溯重計時間。

## 修訂與接續

已確認的故事、角色／世界事實、地點拓樸、鏡頭計畫、節奏約定、參考素材，或角色／攝影機路徑變動時，建立新的 working_revision。記錄變更欄位、受影響成果及未變動證據。只有使用者核准後才升為 approved_revision；被取代的成果標成 superseded，不刪除。提示詞措辭、上傳綁定或已知文字錯誤，可用獨立文字版本修正，不使已核准動畫失效。

只讀取相關紀錄：寫作時看專案摘要和前段連續性；規劃鏡頭時看影片語言與現行計畫；建模時看地點、素材和預算；匯出提示詞時看已核准劇本、分鏡、表演與聲音、時間與結束狀態、素材約定，以及可用軌跡。最終提示詞應包含劇本的故事細節，不只是 Blender 位移。已知的 Blender 手動修改，只有影響下游文字時才同步；不為尋找假設性的偏移而重開 Blender。

模型與動畫核准後，將該修訂升為已核准，階段設為 prompt_export，並交付。核准本身不遞增修訂。技術驗證狀態另行記錄；未驗證項目不阻擋已授權交接。舊專案不需補建空資料夾或虛構報告。

訪談、計畫、採納素材、靜態核准、動畫核准、匯出及段落交付後，逐步更新入口與單集進度。last_checkpoint 必須支援中斷後接續。交接時記錄真實輸出與範圍、角色／道具結束狀態、後續已寫但尚未製作的單集、未寫部分、下次優先閱讀檔案，以及下一個已授權動作或問題。不自動開始下一章。

分開使用 segment_complete、reference_handoff_complete 與 project_complete。使用者端上傳或生成工作，應與助理尚未完成的交付區分。素材升版規則見[素材庫](asset-library.md)。

## 最低交付紀錄

檔案如何分拆可自行決定，但實際訪談、視覺選擇、分鏡展示及各階段意見都必須留存。完整新影片專案應保留原始回答及採納值、具名角色紀錄、攝影／色彩方向、劇本、完整鏡頭表，以及分開的靜態與動畫回饋。包含[參考影片交付](reference-video-delivery.md)定義的 generation_profile 與 delivery_contract。

stage_reviews 要指出展示方式、成果、版本、使用者原話及核准範圍。具名角色紀錄對應 ID、姓名／別名、影像及代理色；角色設定集保存文字身分，影像清單保存真實影像及其代理／最終影片用途。佔位檔不是角色美術圖。分開追蹤 blender_structure_ready、video_appearance_ready，以及工程、影片、文字、上傳綁定和生成成果狀態。角色提示詞不是角色影像。

新增路徑、匯出進度、上傳或核准備註，不必遞增創作修訂。外觀變動會使受影響影像及最終影片提示詞／結果失效；若尺度、動作與結構未變，不會自動使 Blender 成果失效。入口應只保留一組目前指標，以最新現況取代過時的「等待中」或「已完成」敘述，不追加相互矛盾的現況。事件統計由目前事件表推導。
