# 場景、道具與角色的影像素材

本流程用於建築空間、室內、車輛、裝置、家具與重要道具的 Blender 預演。把影像轉為可編輯且有效率的 3D 結構前，先確認類別、形狀、比例、材質分區與視覺語言。單張概念圖無法取代平面配置，也不要求逐像素複製成高面數模型。

## 階段順序與就緒條件

劇本、場景類型與鏡頭意圖確定後：

1. 建立 asset_reference_manifest，列出穩定的素材／影像 ID、區域、錨點、動作道具用途、鏡頭優先順序、尺度與 3D LOD。影像輸入至輸出的相依圖不得形成循環。
2. 沿用或決定影像生成方式。使用者自行生成時，只在專案中建立缺少的同名空白 PNG 佔位檔，並一次交付所有必要提示卡。助理獲授權生成時，依相依順序生成、檢查並保存實際成果，不用佔位檔。首批應同時提供所需場景、道具、缺少的主要角色與預定補充提示詞；獨立影像先於以它們為來源的影像。
3. 登錄實際輸入／輸出、來源、修訂、可擷取的結構及不應複製的外觀。相依母圖必須已登錄且核准，不只是計畫或檔案存在。必要結構圖缺少或未核准時，暫停受影響環境或重要道具建模，不用無根據的盒子跳過。角色外觀同批準備，但不阻擋中性 Blender 代理模型。
4. 結構影像核准後、建模前，選擇直接在 Blender 建立幾何，或依 [Hyper3D 分支](hyper3d-scene-assets.md)生成選定的靜態素材。選 Hyper3D 時先確認 Hyper3D MCP 連線，才估算具名物件範圍與品質；進入 Blender 且需要 Blender MCP 時，另確認其連線。幾何來源只改變選定物件。先建立已採納的拓樸、通道、門、尺度及適合拍攝的視線，再補形狀、接觸面與細節。
5. 粗略動畫開始前，展示靜態場景並取得回饋；之後才共同製作攝影機、主體與道具動畫。

平面圖、現場證據、操作需求與 SceneSpec 的空間約定決定功能、相鄰關係、開口及動線。影像參考決定可見形狀與設計語言，不會默默更改配置。

## 輸入相依與一致性

維護尺寸、座標、相鄰關係、門窗、動線與開啟方向的**空間約定**，以及可見輪廓、零件、材質色塊與設計語言的已核准**主要外觀圖**。宣稱兩張圖是同一素材，不等於實際提供來源影像。

| 影像任務 | 實際輸入及允許變更 |
|---|---|
| 地點或獨立道具的首次設計 | 遵循空間／素材約定；無影像輸入時標明純文字生成 |
| 相鄰區域的首次設計 | 使用空間約定、鄰區已核准母圖及共用門／錨點；未見過的室內是受限制的新設計，不是復原事實 |
| 同一地點／物件的新視角 | 提供已核准母圖及必要共用錨點；只改視角，鎖定結構、左右關係及零件身分 |
| 同一物件的新狀態 | 提供已核准前一狀態；只改指定活動零件／狀態，通常將視角推導與狀態編輯分開 |
| 道具放進環境 | 同時提供環境和道具母圖並指定各自用途；只改約定的擺放與接觸 |

相依影像應持續參照已核准母圖，不只參照上一張衍生圖，以免誤差累積。共用門在內外視角使用同一錨點；表面左右差異應按觀看方向解讀，不任意鏡像。相依圖不能有循環。結構不清楚時，先確定空間約定。

以圖生圖不保證一致；逐張檢查採納成果的零件數、比例、位置、方向、通道與連接。建模前先修圖或明確修訂約定；矛盾影像不能只因提示詞寫「忽略錯誤」就成為核准結構來源。精確幾何需要尺寸、可靠多視角圖或已驗證模型，同時仍須登錄參考。

工具若只能收一張輸入，可把已核准母圖、共用元件及空間圖組成參考板，逐格記錄來源與用途；版面排列不代表實際相鄰關係。不支援影像輸入的工具可探索首次設計，但不能宣稱衍生視角保留身分。記錄實際工具模式與能力；只有 seed 不等於有輸入影像。

## 語言、提示卡與穩定檔名

遵循使用者對工具與語言的偏好。本技能的專案文件與新提示詞預設使用繁體中文及台灣用語；使用者另指定影像提示詞語言時，按要求處理並記錄。工具品牌與影像操作模式是不同選擇。優先重用有效既有素材，不重新生成。交付提示詞本身不等於授權生成。

供使用者閱讀的 image-prompts.md 簡述目的地、順序與實際需上傳檔案。每張提示卡包含序號、檔名、畫面比例、模式、所需來源檔、一至三項簡短視覺檢查點及完整提示詞。相依雜湊、內部 ID、修訂及核准資訊保存在 manifest。連續編號的兩組：

- **先生成獨立影像：**主要地點母圖優先，接著是其他獨立地點、道具與缺少的角色母圖。
- **再生成相依影像：**母圖排在衍生圖前，每張卡片寫出所有實際輸入。選用卡片保留原編號；略過一張不重編後續號碼。

穩定檔名採英文 NN_asset-name.png，通常在超過 99 張前使用兩位數；既有批次新增卡片時接續編號。卡片、計畫、佔位檔、輸出、上傳對應和 manifest 路徑須一致。image_id 與檔名彼此獨立。簡短卡片範例：

    ### 4. 內部大廳
    檔案：04_inner-lobby.png｜比例：16:9｜模式：參照影像編輯
    上傳：01_building-entrance.png，作為共用門口來源
    檢查：同一門框／開門方向；大廳連到已核准樓梯。
    提示詞：[完整說明來源用途、固定零件、允許新設計的室內、
    視角、尺度與排除事項]

交付時將卡片內的佔位文字換成真實內容。獨立卡片標示「上傳：無」。預定檔名或空白佔位檔永遠不是母圖；受阻的衍生圖標為 waiting_for_inputs，仍可先交付其完整未來提示詞。助理生成同樣遵循真實母圖先行的順序。

## 使用者自行生成時的佔位檔

只有使用者自行生成影像時，才使用[佔位影像腳本](../scripts/prepare_image_placeholders.py)。檔案放進選定專案的 image-assets/，或沿用使用者既有資料夾。腳本只依預定畫面比例建立缺少且有效的小型純白 PNG，不含文字或圖案，也不覆寫既有美術圖或佔位檔。下例的 `<skill-root>` 是 `SKILL.md` 所在資料夾，`<project-root>` 是影片專案根目錄：

    python "<skill-root>/scripts/prepare_image_placeholders.py" "<project-root>/image-plan.json" "<project-root>/image-assets" --revision r001 --project-root "<project-root>"

佔位檔路徑、像素尺寸、建立修訂、雜湊及可辨識 PNG 中繼資料，應與實際生成影像的 image_path／output_sha256 分開記錄。空白檔不是可用參考媒體。使用者可用真實輸出取代它，但不要保證瀏覽器會沿用檔名。若提供的是原始下載檔，應對應到預定檔名，且需要 PNG 時以實際編碼轉檔。

使用者回傳後，驗證解碼、佔位標記／雜湊與空白內容、來源輸入，以及該卡片的結構要求。取代同名檔案不等於核准。登錄真實輸出、輸入雜湊及審閱狀態；佔位或未審閱影像不能餵給衍生圖，也不能通過 Blender 就緒檢查。

只有使用者要求或確有衝突時才重新命名既有批次：先檢查來源與目標，在不覆寫內容下改名，保留雜湊／審閱狀態，再同步提示詞、上傳、計畫、manifest、入口與交接。只改檔名不使影像內容失效。

## 素材與影像紀錄

素材紀錄包含 asset_id、role、zone／region、priority、required_for、use_for_blender、image_status（planned／generated／registered）、review_status（pending／approved／revise）、reference_views、帶來源的 scale_anchor、extract_for_blender、do_not_copy、mesh_strategy 和 repeat_strategy。registered 不等於 approved。區域使用 ENV_／ZON_，獨立道具使用 PRP_。單張氛圍圖無法成為每件物件的精確結構來源。

影像紀錄包含 image_id、role、asset_ids、continuity_group_id、image_revision、suggested_filename、operation（initial_design、zone_design、view_derivation、state_edit、composition）、帶修訂的配置約定、canonical_image_ids、planned_inputs、actual_inputs、locked_features、allowed_changes、generation_status、image_path、output_sha256 及 review_status。每項實際輸入要記錄順序、影像 ID、用途、來源修訂／路徑、SHA-256 與使用時的核准狀態；也記錄工具／模型、提示詞版本及可用 seed。不要編造路徑、雜湊或核准。

組合參考板要有自己的實際上傳紀錄，source_images 逐格列出祖先、雜湊、核准、位置及用途。母圖或空間約定變更時，標記受影響的衍生圖和建模基礎為 stale；在修復或重新核准前，保留舊版與輸入歷史。匯出前檢查影像 ID 唯一、檔名對應、來源存在、相依無循環、母圖已核准、修訂及真實檔案雜湊。

## 最低影像集與重要道具設定圖

按鏡頭需要選最少影像：已使用環境區域的清楚視角、連接關係重要的入口／轉角／樓梯／揭露、重要道具，以及少量可重用模組。單張影像可支援多項登錄素材。包含尺度參考與有用輪廓，不生成未使用的反向視角。角色外觀遵循[角色影像規則](character-image-assets.md)：新設定圖左三分之一為頭部特寫，右三分之二為正／側／背全身。它用於 video_generation，不作為 Blender 代理幾何。

新生成的**重要道具**設定圖，預設是一張橫向版面，從左到右顯示**同一件物品**的正面、右側和俯視圖，除非使用者指定其他方向。採正交投影、相同比例，輪廓完整、不裁切、不重疊，結構、零件數、材質／顏色與開閉狀態一致。背景簡單、照明清楚。這是三個視角，不是三件物品或三種動作狀態。助理生成時使用已授權的影像工具並檢查所有視角；使用者自行生成時，取得包含全部要求的完整提示詞。已接受的舊圖可重用，不強迫重生。

可調整的重要道具提示詞：

    為[道具名稱]製作一張橫向三視圖設定圖，風格為[已採納風格]。
    保留[已核准形狀、比例、零件、材質、顏色與狀態]。
    從左到右，以同一比例顯示同一物品的正面、右側與俯視正交圖。
    每個輪廓都要完整、彼此分開；零件數與開啟狀態一致。
    清楚呈現[接觸面或活動零件]。使用簡單背景、均勻照明，
    不含人物、文字、浮水印或場景裝飾。
    [若使用來源影像，說明它的身分用途與允許變更。]

一般場景或非主角影像，應先描述類別與功能、可建模結構、視角、尺度、開口／接觸面、材質區塊和簡潔背景，再加入風格形容詞。不能讓「電影感」把結構參考變成海報。衍生圖提示詞應逐一指定實際輸入的用途、固定的可見特徵及唯一允許的變更，不重複首張純文字提示詞。

## 轉成 Blender 並審閱靜態結果

優先順序：真實／相對尺度、貼地與通行空間；輪廓與類別零件；開口、接觸與操作面；大面積材質區塊及有限倒角；最後才是特寫需要的結構。不要把影像雜訊、反射、污垢、每株植物或每個遠處燈具都建成獨立幾何。可採模組化硬表面、選擇性 Bevel／Mirror／Array、低解析曲線、共享網格、集合實例與 Geometry Nodes。

動畫前要實際展示靜態場景。在本機檢查區域與道具是否易於辨識、室外到室內動線是否連通、構圖是否有層次與可拍攝視線、比例／接觸是否符合已登錄來源、重複物件是否實例化。使用者直接觀看並核准即可，不另加截圖或 AI 審閱。靜態核准只允許開始動畫，不代表動畫已核准。模型與動畫均核准後進入交接。

必要結構若缺失且無可靠來源，提供完整影像提示詞並保留建模待辦；只有外觀美術圖缺失，不阻擋有依據的中性代理工作。真實功能證據優先於美觀但不可能實作的概念圖；應解決影像間的矛盾，不留給 Blender 猜測。
