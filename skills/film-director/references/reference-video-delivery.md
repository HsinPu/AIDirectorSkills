# 參考影片與生成交付

本頁規範平台適配、匯出與資產準備狀態。人工確認後依[交付流程](user-review-and-prompt-handoff.md)辦理；匯出不新增導演或碰撞審閱。

## 確立交付約定

使用者若要求參考影片，匯出已是任務的一部分。記錄 `delivery_contract`：可編輯專案、參考影片、提示詞，以及是否包含助理協助生成／剪輯。付費生成或上傳依實際授權執行。若只要求提示詞或專案，就依較窄範圍交付。

片長與資產規劃需要依賴平台能力前，先記錄 `generation_profile`：目標產品／模型版本、實際介面與模式、畫幅、生成單位、支援的時長／參考／檔案限制，以及查證日期和來源。不阻礙工作的未知事項可保留，不能猜測通用上限，也不能混用一般、延長與特殊長片模式。沿用仍適用的已核實資料；MCP 探測等到 Blender 工作開始。

## 乾淨的參考影片

匯出已確認的鏡頭設計、畫幅、事件與有效影格範圍。可編輯曲線、錨點與輔助線保留在工作用 `.blend`，但提交影片不得出現座標軸、路徑線、選取框、格線、物件名稱、除錯文字或殘留測試音訊。代理顏色用於對應身分，不規定服裝。不可只為隱藏輔助線就移除動作相依關係。

輸出須呈現主體／道具關係的輪廓、朝向、距離、位移與旋轉。關鍵轉向及近景道具在匯出尺寸下要看得清楚。匯出時不可默默改變已確認構圖。景深、動態模糊與晃動只依已採用的意圖加入。

## 分段預演與交付

若成片由多個獨立生成單元接成，先依故事節拍與目標介面的實際能力劃分單元，不預設固定段數或時長。分段表記錄穩定單元 ID、順序、全片與單元內時間、來源影格範圍、接點、對應 `.blend`、參考影片與提示詞。鏡頭切點不必等於生成單元切點；片長變動時重新分配節拍，不把舊動畫直接等速拉長。

每個單元保存可獨立開啟與編輯的 Blender 動畫工程，並各自匯出只含該單元有效畫面的乾淨參考影片。工程可從共用的已確認靜態場景或母檔派生；不因拆分而重建相同場景、角色或重新要求靜態確認。新的或實際修改的動畫完成本批受影響單元後一起展示，提供各段影片、單元索引及全片拼接預覽，供使用者一次審閱；同一次確認分別記錄到各單元版本與範圍，不逐單元再次詢問。未變的已核准範圍可沿用。全片拼接預覽是整體節奏與接點的審閱入口，不能取代各單元工程與參考影片，也不在動畫確認後另增加全片複核。

在相鄰單元接點記錄人物位置與姿態、接觸／牽手、道具持有與狀態、移動方向與速度、攝影軸線與切鏡意圖、光線及連續聲音。下一單元須從相容的狀態接續；若以遮擋或切鏡銜接，明確記錄可變與不可變的部分。計算有效影格時不把上一段尾格重複算入下一段，除非剪輯計畫明確需要停格或重疊。交付清單及狀態逐單元記錄，最終剪輯成片另列為成果。

## 逐鏡素材包與生成單元

交付根目錄以穩定鏡頭 ID 為每個實際切鏡的鏡頭建立獨立資料夾，例如 `SH01_鏡頭名稱/`。資料夾內放該鏡有效時間範圍的預演影片、逐鏡 `prompt.md`，以及該鏡實際引用的人物、場景、道具等媒體；逐鏡清單標明鏡頭與生成單元 ID、全片／單元內時間、素材來源與版本、檔案用途及規劃或實際標籤。跨鏡重複使用的人物或素材，要複製到每個需要的鏡頭資料夾，讓單鏡可獨立檢查，不要求讀者回到共用媒體目錄找檔。只複製採用且該鏡需要的來源；缺少實際媒體時標示待補，不以佔位檔冒充成果。

鏡頭與單次生成不一定一對一。若目標模型的時長或敘事安排使多鏡合併生成，另以生成單元 ID 建立獨立資料夾；每個單元都放自己的完整參考影片、該單元需要的全部媒體與可直接複製提交的完整提示詞。逐鏡提示詞用來核對構圖、動作、身分與剪輯點；只有符合平台能力且明確規劃為單獨生成的鏡頭，才能直接使用逐鏡包提交。單元 `.blend` 可留在製作目錄，並從鏡頭與單元清單連結，不必為每個切鏡重建 Blender 工程。入口索引要能從每鏡找到預演與提示詞，也能從每單元找到正式提交素材，並說明兩者對應與接點。

交付前檢查每個鏡頭與生成單元的提示詞引用都能在其自身資料夾內找到檔案，鏡頭時間連續且對應已採用的單元範圍；複製媒體的大小與雜湊須與採用來源一致。這是檔案交接檢查，不新增美術或動畫核准關卡。

## 有界限的匯出

1. 若同一已確認修訂版、範圍與畫幅的既有檔案有效，就直接沿用。否則先儲存可復原的 `.blend`，並宣告輸出路徑、算圖引擎、影格範圍與批次區間。
2. 優先使用足以滿足需求的 Solid／Workbench 或其他輕量模式；確認 MCP 的「viewport」工具是否實際呼叫目前算圖引擎。不自動提高取樣、解析度或並行數。
3. 除非已有可靠耗時資料，先試一小批確認輸出與成本。有限段落依序匯出，記錄完成範圍；失敗後從未完成處接續。圖片序列可事後編碼，但須考量磁碟容量。
4. 依目標核對實際影格率、尺寸、有效範圍、時長、音訊與編碼。生成單位不包含未使用的剪輯餘量或重複尾段。記錄來源影格、剪輯時間及單位內時間；裁切後同步更新提示詞。
5. 以 `ffprobe` 等可用工具讀取輸出與實際媒體中繼資料，檢查能否解碼、時長、尺寸及範圍。工具不可用時說明哪些仍未驗證；不要只為讀取中繼資料就開 Blender 或重看全片。
6. 記錄相對於專案的路徑、修訂版、FPS、解析度、影格範圍與實際檢查，交付可開啟的檔案。驗證輸出不等於重新作藝術判斷。

以上是工作流程規則，不代表內建算圖器或保證硬性逾時。已開始的高成本評估不會因文字預算而自動中斷。

## 準備狀態與打包

分別追蹤 `text_status`、`reference_video_status`、`appearance_assets_status`、`upload_binding_status` 與 `generation_status`。建模需要真實且已確認的場景／關鍵道具結構圖片。最終生成可能還需要實際參考影片、主要角色美術或其他外觀來源，以及完整提示詞。沒有人物的專案不需要角色美術任務。提示詞、空白佔位檔、檔名或規劃標籤都不是實際媒體或上傳。資產待補時可交付有條件的文字草稿，但不可宣稱整包可直接提交。

交付約定的可編輯專案、乾淨的參考影片、必要的場景／道具／人物圖片與說明，以及各生成單位可直接複製的文字。沿用目前資產，不重複複製歷史或重建代理。只有介面中實際上傳的標籤才算綁定。預設使用一般資料夾；使用者明確要求才建立 ZIP，且只納入目前採用範圍。

為方便使用，將目前採用的上傳媒體依上述鏡頭與生成單元資料夾整理，複製已確認的影片與真實圖片／音訊來源。版本依確認紀錄選擇，不憑修改時間、檔名中的 `final` 或最大編號判定。腳本、紀錄、佔位檔、舊草稿與審閱截圖留在製作資料夾。各包的 manifest 列出穩定資產 ID、來源相對路徑、採用版本、交付檔名、規劃／實際標籤與用途；檢查複製後大小與雜湊。編號檔名不代表已完成上傳綁定。未確認的替代方案在獲准前不要放進採用套件。

收到生成回饋時，記錄輸入媒體／提示詞版本、觀察到的偏差、局部修改與已接受結果。只改有依據的因素；使用者接受結果就停止。不可從匯出檔名推測產品能力，也不可套用其他介面的限制。
