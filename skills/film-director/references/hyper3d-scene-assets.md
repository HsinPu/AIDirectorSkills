# Hyper3D 靜態場景素材

這個選用分支只變更所選物件的來源幾何。仍依照一般 Blender 流程：拓樸與通行空間、環境／道具、靜態審閱、動畫、交付。已核准的專案不用重新開始。

## 必要順序與選擇

本批結構參考圖確認後，提供**直接使用 Blender**或**Blender 加上 Hyper3D MCP**兩條路線。選擇路線前，不預先挑物件或估數量。選擇 MCP 時，先確認安裝、帳號授權和工具確實連線；連線可用後，才估算適合的來源模型，並在同一輪提出兩個有名稱的範圍選項。接著選品質、生成／下載／登錄，然後回到一般 Blender 建模。沿用先前對路線、清單、品質或委託的回答。未回答的選項不等於已接受建議。此操作分支每項決策有兩個實際選項，與創作訪談的三選項不同。

連線時，先探索並載入實際的 Hyper3D 工具。看不到工具不等於未安裝；可用的既有設定應沿用。若尚未設定，依目前 Hyper3D 官方網站、MCP 入口、用戶端說明與 OAuth 引導使用者，並核對最新頁面，因介面可能變動。先前記錄的 Streamable HTTP 位址為 https://api.hyper3d.com/api/mcp；設定前需確認目前官方說明。只有取得授權才修改用戶端設定。網站登入或安裝指令不代表 MCP 已連線；應以唯讀連線、交握或工具證據確認，不用付費試生成。重新載入或暫時斷線時保留已選項目。

連線後計算**新而不重複的來源網格**，不是擺放次數。重點範圍通常含兩至三件重要的不規則靜態物件；中等範圍通常含四至六件，並包含重點物件。這些只是範例，不是配額：若只有一件合適，就只列一件；沒有適用物件，不要編造中等套組。逐件說明物件與效益，允許指名增減。若完全沒有合適物件，說明直接使用 Blender 較合適的原因，讓使用者決定。

## 物件適用條件

一般植物、岩石、規則家具、盒子、簡單容器、燈具、欄杆、門、地板、樓梯及通道，優先用 Blender 或既有輕量素材。固定的不規則家具、雕塑、封閉的雕刻櫃、浮雕、雕花或造型特殊的裝飾燈，若輪廓必須出現在鏡頭中，可能適合 Hyper3D。另有參考圖的浮雕可單獨生成元件，簡單主體仍由 Blender 建立。

預設排除需要精確坐下、倚靠、抓握、開啟、破壞、形變、內部機構或角色接觸的物件，也排除車輛、人物、表演中的動物、手部及決定建築拓樸的構件。應檢視所有鏡頭和後續故事用途，不能只看「背景」標籤。先考慮重用專案或素材庫的既有資產。建模時間須與建置時評估及播放負載分開比較；AI 幾何不一定比較輕。密集穿孔、薄片、層疊內部與精密組裝的清理成本，可能高於可控的手工建模。只有色彩或材質複雜，不足以採用高面數白模。

## 品質與生成

確定物件清單後，提供 **Standard**（預設建議）或 **Fine**，列出各模型目標三角面數與不重複來源模型的合計。生成模型的最低目標是 10,000 個三角面；較複雜的標準模型應高於此值。小型雕刻物可從 10k／20k 起估，雕塑、浮雕或燈具為 20k／40k，複雜家具為 30k／50k。這些是規劃參考值，不保證實際適用。超過約 50k，需具體說明物件或負載原因。Fine 可只用於指定物件。

此分支固定使用 Gen-2.5-Extreme-Low、mesh_mode: Raw、geometry_file_format: stl，且逐模型明確設定 quality_override。Fine 是提高幾何目標，不會暗中切換模型等級。若形狀誤判或零件融合，先改善參考圖／描述，再考慮增加面數。只下載無材質 STL，在 Blender 使用統一白色材質；若 MCP 沒有相關控制，不要保證伺服器端能停用材質生成。選品質前，展示物件清單、影像來源、兩種品質的各模型目標與總量、無材質輸出、目標專案資料夾及 Blender 用途。使用者選定具體清單與品質後即可執行，不再問一次「要開始嗎？」；僅選擇路線不等於授權未定義清單的付費生成。

正式專案要依正確順序使用已接受的來源影像；三視圖合成圖描述的是同一物件。純文字測試須如實記錄。描述應聚焦形狀、比例、構成與必要輪廓，而非故事或機位。送出前探索實際 MCP 參數。先前記錄的本機影像流程使用 rodin_create_uploads、成功的 PUT 與上傳 ID；rodin_import_images 用於對話附件，不是本機路徑上傳。先前記錄支援一至五張影像，應再次確認目前工具能力。

立即保存任務 ID 與實際參數，並輪詢原任務；等待逾時不代表生成失敗。送出結果不明時，不得自動重送。若沒有可追蹤 ID，先請使用者查看 Hyper3D 任務清單，再考慮另一筆付費工作。下載失敗只重試下載，不重做生成。只保存要求的模型檔，並使用永久結果頁面或本機檔案，不依賴會過期的簽署網址。量測 STL 的實際三角面數，不以請求值充數；不可用無意義細分達到下限，也不可暗中減面至低於所選品質。

## 登錄與整合

將檔案放在已綁定專案的模型資料夾，例如 model-assets/Hyper3D/，以 asset_id 加版本命名。記錄用途、場景／被取代物件、選用理由與 Blender 替代方案、來源影像及順序、完整提示詞、任務 ID、參數、狀態、永久結果頁面、原始路徑與雜湊、實際三角面數、工作版本、原點／方向／邊界／比例、Blender 集合／網格、實例用途及階段狀態。任務完成、檔案可用、工作素材就緒與使用者核准靜態場景，是不同狀態。原始 STL 保持不變；單位、方向、原點、貼地與網格修正只在工作複本或素材集合中進行。STL 座標不會自動以公尺計。

取代既有物件時，只替換可見網格或子集合，保留穩定的物件／父層、集合、場景變換、語意錨點與參照。不要重建整個場景或改動無關的機位、人物及動畫；避免新舊網格重疊，或把來源模型顯示在世界原點。依穩定 ID 與匯入紀錄還原，避免重複；保留舊版以供復原。專案局部變體只影響使用它的地方，不改動共享母資產或其他專案。使用專案相對路徑，確保相依檔案可解析。

在一般靜態審閱點展示整合後場景，不逐件素材另行要求核准。核准後照一般規則製作動畫。重複擺放時共享來源網格或集合；實例可減少重複資料，但不會免除繪製成本。可見的展開三角面數約為來源面數乘以相關可見實例數，例如 20k 面的浮雕出現 30 次，單此物件就約 600k 面。預設避免全域 Realize、Make Instances Real、逐處獨立網格及隨機重新散布。遠處使用的低面數代理是另有紀錄的 LOD，不表示採用來源模型符合較低目標。依既有效能預算，只在正常觸發條件下量測。
