# 階段展示與確認

確認的對象是使用者能檢視的具體產物，不是反覆請求同一工作的許可。每次確認只適用於已展示的版本與範圍。圖片路線的分鏡圖，或 Blender 路線的動畫確認後依[交付流程](user-review-and-prompt-handoff.md)辦理。

| 階段 | 向使用者展示 | 繼續工作的依據 |
|---|---|---|
| 訪談或接續 | 工作範圍、已撰寫／已製作／待辦狀態、已回答／已委託／未決事項，以及攝影與色彩方向 | 關鍵創作決策有證據或明確委託 |
| 劇本與分鏡同時展示 | 同一回覆中提供選定範圍的完整劇本、具名角色、具因果的對白、完整分鏡表與攝影／色彩說明 | 已展示項目獲得確認或委託決定；劇本與分鏡可一併確認 |
| 參考路線 | A 漫畫式分鏡圖、B Blender 預演、C Hyper3D 素材＋Blender 預演；已有選擇就沿用 | 選定路線或明確委託，記錄適用範圍 |
| 分鏡圖片（A） | 本批每鏡一張、每張六格的審閱頁（或使用者指定版型）、逐格時間／景別／動作／運鏡對照、實際切點、必要外觀素材及來源用途 | 此批圖片整批確認；下一步是乾淨單格與提示詞交付，不因頁數或格數增加確認點 |
| 圖片資產（B、C） | 必要的場景與道具圖片、角色美術或待補項目、各自用途與確認狀態，並指出下一個可檢視產物是 Blender 靜態場景 | 本批必要的結構圖片已確認；角色美術可同步準備 |
| 靜態場景（B、C） | 已儲存的靜態專案，以及能看清結構的視窗畫面或既有圖片；說明代理形式與下一步 | 對此靜態結果的回饋，或明確免除這個審閱點 |
| 動畫（B、C） | 可檢視的現行動畫或預演，註明時長、範圍與刻意簡化處 | 此動畫結果已確認 |
| 提示詞與參考交付 | A 的乾淨參考圖片或 B、C 的參考影片、先交代來源角色的提示詞、上傳對照表與待辦事項 | 所有約定產物都已提供 |

劇本與分鏡表確認後、製作參考素材前，依[路線選擇](storyboard-image-workflow.md#參考路線選擇)選定 A／B／C。A 不適用 Blender 的靜態與動畫審閱，不須另請使用者免除；圖片確認也不能冒充動畫確認。B、C 的結構圖片確認後，依已選路線建模，不重問幾何來源。C 先確認 Hyper3D MCP 連線，再估算素材範圍與品質。這項準備不能取代靜態確認，也不為每個生成資產增設確認。實際透過 Blender MCP 操作場景前，另確認 Blender 執行個體的連線；兩項檢查各有用途。

若使用者只要求 Blender 連線或運鏡測試，展示時標明測試涵蓋的鏡頭、角色與道具，並說明整段聯合粗動畫的待辦。測試只確認已展示的範圍，不代表整段動畫已完成；後續仍遵守靜態場景與動畫各自的確認點。

儲存並展示靜態場景後，暫停 Blender 寫入。不要用一段長腳本把靜態建模與動畫合併完成，事後才請使用者審閱。使用者可以直接在 Blender 檢視，不一定要截圖；只有路徑或物件數量，不能證明場景已展示。等待期間可整理紀錄與已確定文字，但不要寫入動畫關鍵影格。靜態階段可以完成靜止姿勢的骨架綁定與規劃中的可見接觸手部結構，不可先做姿勢及相機動畫。

預設在同一輪展示劇本與分鏡；它們可有各自的 `stage_reviews` 紀錄，指向同一則回覆。使用者若只要劇本或分開交付，就遵守該範圍。未展示的分鏡不可標為已確認。展示靜態結果後的「繼續」可能表示接受它並進入動畫；展示前的「繼續」只表示推進目前階段。圖片確認或允許開始建模，不等於確認尚未存在的模型。

「你決定」通常只委託目前的創作選擇，不免除後續產物審閱。只有明確要求不經靜態及／或動畫確認就繼續，才算免除相應檢查點。記錄使用者原話與範圍；已獲免除就不要重問。後續修改只使受影響範圍的確認失效。

## 整批製作與審閱

預設以目前已確認的整支作品、單集或選定段落為批次範圍，不以每個分鏡或生成單元增加確認次數。劇本與完整分鏡確認後，同階段內自主完成已授權工作；A 一次展示全部分鏡頁與必要外觀素材，B、C 在圖片素材、靜態場景、動畫預演各階段結束時一次展示本批全部成果。B、C 的靜態與動畫仍是兩個分開的審閱階段；製作期間的技術分批、儲存或工具限制不構成使用者審閱點。只有使用者要求逐項審閱，或有影響成果且無法自行解決的缺失／衝突時，才針對必要項目提問；未受影響的同階段工作繼續。

素材按相依順序製作，同批母圖的草稿使用依[影像素材流程](reference-image-driven-assets.md)辦理。B、C 一次展示全部靜態場景與各場景代表構圖，取得確認後再製作本批全部動畫。動畫審閱同時提供各段預演、鏡頭／單元索引；多段作品另提供全片串接預覽作為整體節奏與接點的審閱入口，各段工程與參考影片仍須保留。此預覽屬於原本的動畫審閱，不是確認後新增的全片複核。

使用者對已列明並展示的整批成果表示「可以」、「繼續」或「這批都可以」時，可一次確認該批所有項目；將同一回覆證據對應到各項版本與範圍，不逐項再次詢問。只接受部分項目時分別記錄；修訂後合併展示受影響項目，未變且已確認的項目沿用。沒有展示的項目不能藉整批確認標成已確認。

## 證據紀錄

在 `project-state.json` 的 `stage_reviews` 或同等紀錄中保存：`stage`、`artifact_ref`、`revision`、`presentation`、`presented_at`、`status`、`user_evidence`、`approved_scope` 及 `next_stage`。整批審閱可用 `review_batch_id` 與 `artifact_refs` 列出全部產物，或讓各產物的獨立紀錄引用同一批次與使用者回覆；每項保留自己的版本、展示證據及核准範圍。`status` 可為 `not_presented`、`awaiting_user`、`approved`、`revise` 或 `explicitly_waived`。

記錄產物實際如何展示，保留使用者原話與脈絡。可沿用目前工作階段或紀錄中可靠的確認，不重問；不可為舊專案虛構確認。人工確認不代表 FPS、碰撞或生成已經過技術測試。創作決策的委託與產物確認是不同事實。
