# 階段展示與確認

確認的對象是使用者能檢視的具體產物，不是反覆請求同一工作的許可。每次確認只適用於已展示的版本與範圍。動畫確認後依[交付流程](user-review-and-prompt-handoff.md)辦理。

| 階段 | 向使用者展示 | 繼續工作的依據 |
|---|---|---|
| 訪談或接續 | 工作範圍、已撰寫／已製作／待辦狀態、已回答／已委託／未決事項，以及攝影與色彩方向 | 關鍵創作決策有證據或明確委託 |
| 劇本與分鏡同時展示 | 同一回覆中提供選定範圍的完整劇本、具名角色、具因果的對白、完整分鏡表與攝影／色彩說明 | 已展示項目獲得確認或委託決定；劇本與分鏡可一併確認 |
| 圖片資產 | 必要的場景與道具圖片、角色美術或待補項目、各自用途與確認狀態，並指出下一個可檢視產物是 Blender 靜態場景 | 本批必要的結構圖片已確認；角色美術可同步準備 |
| 靜態場景 | 已儲存的靜態專案，以及能看清結構的視窗畫面或既有圖片；說明代理形式與下一步 | 對此靜態結果的回饋，或明確免除這個審閱點 |
| 動畫 | 可檢視的現行動畫或預演，註明時長、範圍與刻意簡化處 | 此動畫結果已確認 |
| 提示詞與影片交付 | 對應影片、先交代來源角色的提示詞、上傳對照表與待辦事項 | 所有約定產物都已提供 |

結構圖片確認後，選擇直接在 Blender 建立幾何，或以 Hyper3D MCP 生成選定的靜態素材後匯入 Blender。若選 Hyper3D，先確認 Hyper3D MCP 連線，再估算素材範圍與品質。這項準備不能取代靜態確認，也不為每個生成資產增設確認。實際透過 Blender MCP 操作場景前，另確認 Blender 執行個體的連線；兩項檢查各有用途。

若使用者只要求 Blender 連線或運鏡測試，展示時標明測試涵蓋的鏡頭、角色與道具，並說明整段聯合粗動畫的待辦。測試只確認已展示的範圍，不代表整段動畫已完成；後續仍遵守靜態場景與動畫各自的確認點。

儲存並展示靜態場景後，暫停 Blender 寫入。不要用一段長腳本把靜態建模與動畫合併完成，事後才請使用者審閱。使用者可以直接在 Blender 檢視，不一定要截圖；只有路徑或物件數量，不能證明場景已展示。等待期間可整理紀錄與已確定文字，但不要寫入動畫關鍵影格。靜態階段可以完成靜止姿勢的骨架綁定與規劃中的可見接觸手部結構，不可先做姿勢及相機動畫。

預設在同一輪展示劇本與分鏡；它們可有各自的 `stage_reviews` 紀錄，指向同一則回覆。使用者若只要劇本或分開交付，就遵守該範圍。未展示的分鏡不可標為已確認。展示靜態結果後的「繼續」可能表示接受它並進入動畫；展示前的「繼續」只表示推進目前階段。圖片確認或允許開始建模，不等於確認尚未存在的模型。

「你決定」通常只委託目前的創作選擇，不免除後續產物審閱。只有明確要求不經靜態及／或動畫確認就繼續，才算免除相應檢查點。記錄使用者原話與範圍；已獲免除就不要重問。後續修改只使受影響範圍的確認失效。

## 證據紀錄

在 `project-state.json` 的 `stage_reviews` 或同等紀錄中保存：`stage`、`artifact_ref`、`revision`、`presentation`、`presented_at`、`status`、`user_evidence`、`approved_scope` 及 `next_stage`。`status` 可為 `not_presented`、`awaiting_user`、`approved`、`revise` 或 `explicitly_waived`。

記錄產物實際如何展示，保留使用者原話與脈絡。可沿用目前工作階段或紀錄中可靠的確認，不重問；不可為舊專案虛構確認。人工確認不代表 FPS、碰撞或生成已經過技術測試。創作決策的委託與產物確認是不同事實。
