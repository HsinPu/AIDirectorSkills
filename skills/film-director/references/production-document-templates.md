# 創作與製作文件範本

在選定的獨立專案中使用這些範本。隨工作進度建立有內容的檔案，不預先建立空檔。短片可合併相鄰表格，但仍須保留訪談證據、視覺決策、分鏡展示及階段回饋。下列路徑是相對於專案根目錄的建議。

## 1. 訪談與創作簡報

預設在對話中，以三個 A／B／C 選項詢問未定的創作問題，並同步到 canon/creative-interview.md 等紀錄。若目前對話規則要求透過檔案傳遞，將完整問題、選項與作答說明寫入專案並連結。記錄實際原因與方式，不將工作階段限制說成使用者的永久偏好。

| 問題 ID／主題 | 既有事實或實際問題與原始選項 | 使用者原話或來源 | 採納值／委託範圍 | 狀態／修訂 |
|---|---|---|---|---|

分開記錄 prepared_in_document、presented_in_chat、document_link_delivered，以及使用者回答／採納。檔案、單一建議或排入佇列的面板都不是答案。未回答的問題維持開放。在 revisions/<revision>/creative-brief.md 摘要目的、預期感受、故事界線、具名人物、片長／畫面比例、攝影／色彩、聲音、素材、工作量、交付及未決項目。沒有來源，不把姓名或視覺選擇標為已確認。

互動約定可放在訪談中，或獨立的 canon/interaction-contract.md，並索引為 creative_documents.interaction_contract。選用的 interview_question_states 可含 status、options_ref、presentation_mode、presentation_status、three_options_presented_in_chat、answer_form、user_evidence、adopted_value。自由文字即使沒有 A／B／C 字母，也可能確認一項事實。暫時性的工作階段限制應與長期使用者要求分開。

## 2. 角色與視覺身分

canon/character-bible.md 可採用以下欄位：

| 內部 ID | 姓名或固定稱謂 | 別名 | 關係與目標 | 外觀、服裝、聲線 | 影像 ID | 代理色 | 來源／狀態 |
|---|---|---|---|---|---|---|---|

主要角色應有穩定易讀的姓名或選定稱謂。刻意匿名的乘客或店員可保留稱謂；A／B 不應是預設角色名。不同狀態影像共用同一角色 ID。準確記錄角色、影像與代理模型的對應。

## 3. 攝影、色彩與聲音

canon/screen-language.md 可採用：

| 面向 | 採納值 | 範圍或例外 | 使用者／證據來源 |
|---|---|---|---|
| 媒介與參考 | 真人、動畫或其他；具體借鑑面向 | 不承襲無關情節或演員 | |
| 視角與景別 | 觀看距離、人物與空間比例 | 鏡頭例外 | |
| 基本運鏡與手持 | 固定／運動原則、幅度與可見特徵 | 啟用的鏡頭／事件 | |
| 鏡頭長度與剪接 | 長鏡頭、一鏡到底、混合或密集剪接 | 剪接動機與不中斷事件 | |
| 色彩 | 主副色、冷暖、飽和度、對比、膚色與陰影 | 場景變化 | |
| 光線與質感 | 主光來源／方向、硬度、材質、顆粒／清晰度、景深 | 與中性素材照明的差異 | |
| 聲音 | 對白、環境音、音效、音樂、旁白、字幕 | 靜默與口音 | |
| Blender 與最終影片 | 大致攝影／代理動作與最終外觀／表演 | 若有選用，微幅手持可留到最終影片 | |

這些是可執行的視覺指引，不需要指定攝影機品牌，也不要求中性預演算出最終光線。

## 4. 劇本、節拍與分鏡

story/<scene>_script.md 記錄場景／時間、具名人物、可見行為、必要對白與聲音。可附節拍表，也可合併：

| 節拍／時間 | 目標與觸發 | 動作、反應、結果 | 觀眾資訊與情緒 | 聲音／停頓 | Blender 表現 | 最終影片細節 |
|---|---|---|---|---|---|---|

未錄製的對白，依預期講法估算並標註；有實際朗讀或音檔時用實際時長。允許對白、呼吸、動作與攝影機重疊。字幕放得下，不代表對白真的說得完。

預設在一則計畫回覆中展示目前範圍的完整劇本和 revisions/<revision>/storyboard.md，提供永久連結。分鏡要填寫真實內容，不能只寫「同劇本」或內部 JSON：

| 鏡頭／時間／時長 | 景別與機位 | 開頭／結尾構圖與位置 | 動作／反應 | 運鏡／手持 | 資訊／情緒 | 對白／聲音／剪接 | 光線／色彩 |
|---|---|---|---|---|---|---|---|

說明鋪陳、揭露、停頓與剪接邏輯。多人鏡頭標明發起者、目標、承受者與鏡頭主體。運鏡轉移時，分開移動時間、主體可讀時間與反應時間。長鏡頭可在同一 SH_010 下列 BT_01、BT_02，標明「連續，不剪接」。實際顯示表格，不只報數量或路徑；長篇故事只展開本次選定章節。

## 5. 展示與階段回饋

使用 stage_reviews 或等效紀錄，保存階段、artifact_ref、修訂、展示方式、presented_at、狀態、使用者原話、核准範圍及下一階段。劇本與分鏡可在同一則回覆展示，但核准範圍需分開。靜態模型與動畫也各有獨立紀錄。狀態檔寫「已展示」，須有回覆或實際觀看證據支持。

更新 PROJECT.md 的目前階段、連結及真實待辦事項。提示詞階段讀取已核准素材，局部補正遺漏，不重開整份訪談。維護技能不會自動遷移使用者專案。

## 6. 系列範圍與接續

story/sequence-map.md 可採用：

| 單集／場景 ID 與順序 | 情節與來源文字 | 寫作狀態 | 預演狀態 | 提示詞狀態 | AI 影片狀態 | 目前範圍／下一步 |
|---|---|---|---|---|---|---|

寫作可為 missing、outline、source_supplied、draft、approved；預演可為 not_started、static_in_progress、static_approved、animation_in_progress、animation_approved、reference_exported；提示詞可為 pending、partial、delivered；影片可為 not_started、generated、user_approved。各狀態互不推定。

選用的狀態欄位可包含 project_kind、帶 action／scene_ids／source_script_ref／source_range／rewrite_scope 的 work_scope、creative_documents 參照、列出已完成範圍與來源的 last_checkpoint，以及列出下一個已寫或未寫場景、next_action、action_status、read_first 的 resume_context。已有已核准劇本，不表示要重寫。不要只為填範本而遷移舊專案。

canon/world-bible.md 保存時代、世界規則、地點、時間軸與已確定事實。canon/creator-preferences.md 保存觀眾體驗、主題、界線與範圍。canon/continuity-ledger.md 記錄場景／修訂、時間／地點、每個人的位置／狀態／所知、道具歸屬／損傷、觀眾所知／未解伏筆、下一場不變條件及來源。單場的大幅手持或緩慢對白，不會成為整個系列的規則。

段落交接時，連結專案和進度檔。segment_complete 或 reference_handoff_complete 不代表 project_complete。

## 7. 角色設定圖、代理、互動與上傳媒體

角色紀錄連結 character_id、設定圖版本、左三分之一頭部／右三分之二正側背全身配置、同一人物的狀態圖，以及代理的 H／W／D、身體長度、球心、來源、四骨鏈與支撐。跨集沿用尺寸。確實需要可見手部操作的鏡頭，才記錄 contact_hand_plan 的左右側、道具、區間、持有者及連續性；不能據此推定所有鏡頭都需要手部表演。

多人動作只在相關處加上：

| 事件 ID／時間 | 發起者對目標／類型 | 準備／作用時間 | 距離／方向／結果 | 其他參與者 | 後續狀態／佔用空間 |
|---|---|---|---|---|---|

攻擊與倒下等次數應由事件推導。每件可見道具都要記錄影片結構上呈現什麼、文字補充什麼、哪張影像提供外觀。集中式媒體清單記錄素材 ID、來源路徑、已核准版本、交付檔名、大小／雜湊、預計或實際標籤、用途與狀態。工作版本、使用者核准版本與上傳綁定版本各自區分。
