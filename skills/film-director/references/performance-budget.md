# 硬體與效能預算（1.2）

依本文件規劃實際製作負載與使用者要求的效能檢查。模型與動畫確認後直接進入提示詞交付，不新增硬體探測、校正或基準測試。

## 硬體探測與軟性起始預算

執行[硬體探測腳本](../scripts/probe_hardware.py)：`<skill-root>/scripts/probe_hardware.py --output <workspace>/hardware-profile.json`，取得唯讀硬體資訊；`<skill-root>` 是本技能 `SKILL.md` 所在資料夾。透過 MCP 檢查 Blender 版本、實際使用的 GPU 算圖器／後端、算圖引擎、目標 FPS，以及 `VIEW_3D` 的實際大小／模式。系統顯示的顯示卡清單不等於 Blender 使用的 GPU。Windows 的 `AdapterRAM` 可能不可靠；VRAM 優先用廠商工具確認。未知或統一記憶體就是未知，不等於零或獨立 GPU；不同裝置的 VRAM 不可相加。依[硬體設定檔 Schema](hardware-profile.schema.json)記錄。

只有裝置、驅動程式、Blender、引擎、視窗及基準測試版本仍適用時，才沿用設定檔。繁重工作前更新可用 RAM／VRAM。電力、溫度、遠端桌面或其他負載可能需要降低預算並做針對性測量。探測器不讀取序號、帳號或網路資料，也不安裝相依套件。

只有需要時才用實際評估過且可見的場景校正。先暖機，再測量帶固定 seed 的實例、植被風動與移動相機；可行時骨架另測。以有界限的 1 倍、再 2 倍增量測試，不一開始就塞滿配額。除非使用者要求保留，否則還原暫時狀態。

| 指標 | 低 | 中 | 高 |
|---|---:|---:|---:|
| 候選主機 | 未知／整合顯示，或 RAM 少於 16 GiB | RAM 至少 16 GiB，且目前使用的獨立 VRAM 至少 6 GiB | RAM 至少 32 GiB、目前使用的獨立 VRAM 至少 12 GiB，CPU／評估能力也足夠 |
| 展開後可見三角面數 | 500,000 | 1,500,000 | 3,000,000 |
| 基礎 Objects | 500 | 1,500 | 3,000 |
| 目前鏡頭的實例數 | 5,000 | 20,000 | 50,000 |
| 預估圖片貼圖，MiB | 512 | 1,024 | 2,048 |
| 初始即時模式 | Solid／720p | Solid 或輕量 Eevee／1080p | 輕量 Eevee／1080p |

以上是保守估計，不是保證，也不是要填滿的目標。通常以 24 fps 為目標；有需求時使用 30 或 60 fps。只有測過該模式與解析度，才可稱該級距「已校正」。目前資源不足時應下修。新 RAM 工作量先控制在可用 RAM 的一半以下，新 GPU 配置先控制在空閒 VRAM 的一半以下；若可能，獨立 GPU 另保留約 `max(2 GiB, 總量的 20%)`。統一記憶體只有一個共用池；整台裝置的 GPU 使用量不全是 Blender 所用。

## 測量與解讀

[inspect_performance.py](../scripts/inspect_performance.py) 透過 `execute_blender_code` 唯讀檢查目前影格，不改影格、不寫檔，也不推算 FPS。它統計來源與評估後的網格幾何、實例、遞迴 Realize，以及保守估算的相機球體視錐候選項目。預設防護上限為 250,000 筆或 12 秒；迴圈外的遍歷可能更久，結果截斷時不能宣稱有有效上界。

分開統計基礎 Objects、獨立來源網格／三角面、評估後實例與可能可見的實例。Realize 會產生實際幾何，但未必建立 Objects；Make Instances Real 則會建立 Objects。不要只為統計就 Realize。展開後可見三角面數合併非實例的評估後幾何，以及候選實例的來源幾何，並避免重複計算巢狀實例。視錐／邊界只估算上界，不是精確遮擋。

分清程序工作集、可用 RAM、裝置 GPU 使用量及預估圖片記憶體；未知值用 `null`。壓縮檔大小不是常駐貼圖成本。設定影格加相依圖的 p50／p95 只測評估時間，不含 MCP、截圖、離線算圖或實際呈現 FPS。可靠的即時播放測量須記錄可見視窗、同步模式、視窗大小、著色模式與測量區間。跳格可能掩蓋未趕上的影格。無法測量時設 `viewport_fps=null`、`viewport_status=unverified`；使用者直接觀看屬於「觀察」，不是「測量」。

24 fps 的單格時間為 41.7 ms、30 fps 為 33.3 ms、60 fps 為 16.7 ms。有可靠樣本時，將呈現 p95 與目標單格時間比較，並保留約 30% 的評估／繪製餘裕。只有評估數據不能證明即時播放順暢。

出現預算警告後，在維持構圖與接觸代理的前提下，依序降低畫面外仍被評估的內容、遠景 LOD、實例密度、材質／貼圖／陰影、模擬，再處理細分。記憶體不足或未核准的全量 Realize 應停止。例外情況要記錄鏡頭價值、證據與修訂後預算。結構、評估成本、視窗流暢度與預覽完整度分開判斷。

Fast 檢查沿用預算與既有統計，不呼叫完整 `inspect_performance.py`，也不測播放。只有負載變化有影響、使用者回報卡頓，或明確要求複核時才測量。快取規則只是程序規範，未實作持久儲存。追蹤來源修訂版、影格、場景／View Layer、範圍、資產／GN 版本、GPU／引擎／模式與方法。密度、幾何、算圖設定、GPU、視窗或依相機決定的可見性改變時，相關測量失效。只改相機時，來源幾何數量可能仍可沿用，但可見實例與視窗證據會失效。不可把舊數值重新標成新數值。

## 重複物件、大場景與 Modifier

不要為每片草葉、樹葉或顆粒建立獨立 Object、專用網格、骨骼或關鍵影格。少量需互動的特寫可列為例外並計入。起始使用兩到四種共用草叢原型，每種約 20–100 個三角面，仍須符合總幾何預算。可用 Distribute Points on Faces 加 Instance on Points，或使用固定 seed 的共用點雲，控制密度、比例、區域與風動。預設避免 Realize；只有接觸或匯出確實需要幾何時，才估算並轉換一小份。隱藏的高 LOD 分支仍可能被評估，應測量。

近景保留輪廓與接觸，中景使用低面數群集，遠景用地面色塊或稀疏不透明片。透明材質的重複繪製與陰影成本，可能高於不透明低面數幾何。實例化前，可讓少量共用草叢頂點依根部到尖端權重做二到四個相位的動畫；遠景也可能只需實例的小幅旋轉。只改 normal、bump 或顏色，不能產生輪廓上的風吹效果。不要每格重建散佈。

地形起始可分成約 20–50 公尺的區塊，再依鏡頭調整。只有名稱不會讓 Blender 自動具備串流、LOD 或剔除。應實作 Collection 排除、實例化前選擇、連結載入或代理，並驗證相依圖負載確實下降。相機不可見或設為 Hide Render 不保證不被評估；還要保留陰影／反射相依關係。連續鏡頭需有穩定可見區與餘裕，或以穩定 ID 配合距離選擇，不可每次相機移動就隨機重新散佈。檢查鏡頭內是否出現 LOD 跳變。

Bevel 起始用一或兩段視窗細分，主角道具可用三段；Subdivision 起始為零或一，主角道具可用二。超過三個 Boolean、巢狀 Realize 與大型 Repeat Zone 須評估成本。不要套用一套通用 Modifier 組合。Array 常產生實際幾何，而非實例。共用 1K–2K 貼圖／atlas 可作為起點。關閉未使用的皮膚、毛髮、體積、布料與流體工作。有限範圍模擬用固定 seed 快取。公里級場景使用局部原點。

每批工作依物件集合、資產、鏡頭或有限影格範圍定義，附前次結果、儲存檢查點與停止條件。成本未知時從小批開始；同時只跑一項繁重 Blender 工作。逾時先檢查執行中或部分完成狀態，再重試。約定參考影片依序匯出，記錄影格、解析度、引擎與分段進度。腳本的軟性時間限制無法防止所有主機卡住情況。
