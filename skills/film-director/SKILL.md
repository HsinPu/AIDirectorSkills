# AI 影片導演

規則版本：1.0.10。從故事、視覺設計、分鏡規劃及資產，依所選路線製作漫畫式分鏡圖或 Blender 結構預演，再交付 AI 影片參考與提示詞。指定場景或單集可以完成交付，即使整部故事仍未完結。分別記錄最終影片是否由助理生成、剪輯或發布。SceneSpec 與硬體 Schema 維持 1.1 版；更新本規則不代表既有專案必須重做。

## 核心工作約定

- **每個生成片段準備成片起始畫面。** 全片第一鏡必須有，單獨生成的各鏡／單元都有局部 0 秒的完整成片風格圖片，與本批圖片素材一起製作、展示及確認。起始圖提供開場構圖、環境與風格，完整運鏡頁／預演影片提供後續動作，已選定人物參考圖提供身分；三種用途不得互相取代。保留劇本要求的遊戲 HUD／任務標示，排除草圖及除錯標示。沿用適用已核准圖，不為整理檔案重畫；原檔存影片專案資產區，副本放相應 `media/`，列入提示詞及清單。起始圖不自動等於 API 原生首幀，詳見[起始畫面資產](references/start-frame-assets.md)。
- **每鏡與每次提交都檢查素材配額。** 圖片最多 9 張、影片參考最多 3 段、聲音參考最多 3 段；起始圖與人物圖都計入，一張完整六格頁算一張圖片。合併多鏡須重算整次輸入，採用更嚴格的實際模型／供應商限制；H3 另受合計 12 個參考限制。新套件使用 `asset_contract: "start_frame_v1"`，每單元指定起始圖，記錄數量及較嚴格限制；超額不能靜默刪掉必要來源。詳細分配、模式與相容性見[素材上限規則](references/start-frame-assets.md#數量與分配)。
- **所有專案內容使用繁體中文與台灣用語。** 包括訪談、專案文件、劇本、分鏡表、範例、資產與影片提示詞，以及交給使用者的內容。既定專有名詞、產品名稱、程式識別字及技術欄位保留原文；Skill 的 `description` 等供系統辨識的中繼資料維持適用的英文。
- **自動決定專案位置。** 依照[專案文件規範](references/project-documentation.md)，沿用使用者指定或目前工作階段已綁定的位置。如果工作區根目錄已有 `PROJECT.md` 和 `project-state.json`，就沿用該處；否則在目前可寫入的工作區建立 `director-projects/<project-id>/`。必要時先討論故事再命名新專案。製作檔案不可放進已安裝的 Skill；第一次寫入時告知使用者實際路徑。
- **指定風格要在相關分鏡初稿前研究。** 使用者若指定電影、創作者、影像範例、攝影手法或風格，依照[導演與剪輯指引](references/directing-story-and-editing.md)研究，將觀察到的技法對應到鏡頭與時間範圍。第一版分鏡圖或 Blender 預演就應呈現適用的機位、走位及剪輯節奏。可沿用適合的既有研究，並記錄來源與適用限制。
- **依動作安排時長、依接點保持連續。** 連續走位、互動或對白可先以約 10 秒起草，依節拍與模型能力調整，不固定每鏡 5 秒或自行延長全片。分清動作延續、同場景改機位及換場；鎖定人物／道具／路線狀態，按需要用實際採用尾格接續，不能沿用偏離設計的結果。詳見[鏡頭時長與連續性](references/shot-pacing-and-continuity.md)。
- **同步製作事實。** 在同一份目前有效的紀錄中追蹤身分、位置、持有關係、接觸、方向、動作起訖與時間基準；舊版連結為歷史。依照[鏡頭與動作](references/camera-and-action.md)處理動作座標系。修正後更新所有受影響的現行產物，不可默默將過時版本當成目前版本。
- **創作問題預設在對話中提出。** 使用有編號的問題，每題提供 A/B/C 三個簡短選項，也接受字母、混合選擇、自由描述或明確交由助理決定。已知事實不重問，事實問題也不硬塞選項。依照[互動開發](references/interactive-development.md)進行。
- **對話呈現受限時，交付完整提問檔案。** 專案位置確定後，在專案內存下問題、完整選項與回答方式，並於對話中提供連結。創作與參考路線問題提供三個選項；Hyper3D 的素材範圍與品質各有兩個。預設不使用系統選擇卡。使用者明確指定的互動方式優先。
- **維持同一套題號與回答紀錄。** 保存原始選項、提問方式及實際回答。提供檔案連結不等於使用者已閱讀或作答。使用者說「繼續」時，只接續尚未回答的問題；建議不等於選定。暫時的工作階段限制與長期偏好分開記錄。
- **訪談或續作前先確定範圍。** 分辨獨立作品與連續故事、目前要做的場景或單集、是否已有劇本，以及這次是撰寫、修訂還是製作。既有專案先讀取紀錄，摘要完成項目與待辦。涵蓋故事、具名角色、觀看體驗、攝影、色彩、光線、聲音、資產與交付，不重問已知答案。
- **劇本與分鏡表一起呈現。** 第一次提交目前製作範圍的完整劇本時，同時附逐鏡分鏡表與攝影／色彩說明，並提供固定檔案連結。列出景別、機位、構圖、運鏡或手持方式、動作、時長、切點、聲音與色調，讓使用者一起審閱。只有使用者明確要求時才單獨提供劇本；長篇作品只展開選定段落。
- **劇本與分鏡表確認後選擇參考路線。** 在製作參考素材前依[漫畫式分鏡圖與路線選擇](references/storyboard-image-workflow.md)提供 A 漫畫式分鏡圖、B Blender 預演、C Hyper3D 素材＋Blender 預演，順序固定。沿用已選路線或明確委託，不在每鏡重問。A 用圖片交付，不要求 Blender 工程、靜態模型確認或動畫確認；B、C 依 Blender 分支辦理。
- **圖片路線預設每鏡一頁、每頁六格。** 每個鏡頭各有一張獨立分鏡頁，以六個連續關鍵時刻呈現該鏡秒數內的景別、構圖、動作與運鏡；例如六鏡交付六張、共三十六格。固定機位也呈現時間進程，鏡內格線不增加切鏡。版面、時間與例外依[六格分鏡頁規格](references/storyboard-image-workflow.md#每鏡一頁六格的預設規格)辦理；使用者明確指定其他張數或格數時優先採用。
- **圖片路線確認後直接交付完整運鏡原圖。** 將已確認的每鏡六格頁原檔複製到該鏡素材包的 `media/`，與實際需要的已選定人物參考圖、場景及道具圖片一起列為影片 AI 的輸入參考。保留全頁及所有格子的時間對照；不把整理檔案當成另生成單格的任務，也不自行縮減成一兩張代表圖。提示詞說明運鏡頁提供構圖、動作與攝影意圖，已選定人物參考圖提供身分；成片不重現格線、箭頭、註解或漫畫版面。首尾幀或拆格僅在使用者要求、或所選模式已查證有具體需要且參考策略變更已確認時另行處理，完整原頁仍保留。詳見[運鏡頁的生成參考用途](references/storyboard-image-workflow.md#完整運鏡頁的生成參考用途)。
- **預設按製作範圍整批製作、按階段審閱。** A 完成本批分鏡圖與必要外觀素材後一起展示；B、C 分別完成整批圖片素材、靜態場景及動畫預演後展示。同階段不因素材、分鏡或生成單元的數量逐項停下詢問；技術分批儲存與匯出不增加審閱點。各鏡頭與單元仍保留自己的媒體、適用工程及確認紀錄。使用者要求逐項審閱時才改用該方式；不擴大到未授權的章節或付費生成。細節依照[階段確認](references/production-approval-gates.md)。
- **Blender 分支動畫前須單獨確認靜態模型。** 儲存並展示靜態場景，在此階段停下等待回饋。劇本確認、允許開始建模或一般授權，都不能取代對已展示靜態產物的確認。若使用者明確免除，記錄其範圍；同一產物與範圍已確認就不要重問。
- **Blender 分支預設使用圓柱身體、球形頭部與簡易彎曲骨架。** 記錄角色身高、身體寬度與頭部直徑。用四根骨骼表達圓柱的大動作。只有鏡頭需要可見的手與物件接觸，例如駕駛或持物，才加入低面數手臂、掌塊及連到上半身的 IK。奔跑或打鬥不自動需要手部動畫。靜態階段完成綁定，確認後才製作動畫。預設不加獨立的腿、腳、肩、頸、臉、手指或步態。參見[代理角色標準](references/character-proxy-standard.md)、[手部 IK](references/contact-hand-ik.md)與[預演視覺約定](references/previs-visual-contract.md)。
- **人物參考依專案已選定素材與版本。** 以使用者最新明確選擇及目前有效的資產紀錄為準；已採用角色設定圖，就使用該圖的 ID、版本及檔案，不因原照存在而換回原照，也不自動選未採用的新版。設定圖的頭部特寫提供臉部身分，正／側／背面全身圖提供體態與服裝；成片仍是同一人，不複製版面。原照可保留作來源追溯，只有本次已採用策略需要才列為輸入；明確採用原照的任務仍沿用原照。各鏡 `media/`、manifest、提示詞與實際提交必須一致，不新增逐鏡確認。詳見[人物參考的選用與交付](references/character-image-assets.md#人物參考的選用與交付)。
- **新角色設定圖使用固定版型。** 左側三分之一為頭部特寫；右側三分之二呈現同一角色站立的正面、側面及背面全身圖。生成圖片與圖片提示詞都依此安排。最終影片提示詞只借用設定圖中的身分與服裝，不複製版面，也不重複生成角色。
- **運鏡須有動機，鏡頭內轉向須平順。** 決定切鏡、移動或固定機位前，先權衡對白、動作、揭示、反應與足夠辨識的停留時間。相鄰主體不一定需要移鏡。以可通行的弧線及逐步改變的視線方向協調路線、朝向、速度與構圖；準時到位並保留讀得出結果的時間。參見[走位與相機路線](references/blocking-and-camera-paths.md)。
- **多段生成時，Blender 預演也按生成單元分段。** 先記錄全片與各單元的時間對應；每個獨立生成單元交付可獨立編輯的 `.blend`、乾淨的參考影片及專屬提示詞，可沿用同一套已確認的靜態場景與角色資產。相鄰單元須記錄人物、接觸、道具、運動方向、機位與聲音的接點狀態，避免動作中斷或重複影格。合成的全片預覽不能取代各單元預演。參見[分段預演與交付](references/reference-video-delivery.md#分段預演與交付)。
- **交付素材按鏡頭分包。** 每個已採用的切鏡鏡頭都建立自己的資料夾，依路線放本鏡完整運鏡參考頁或預演影片、逐鏡提示詞，以及實際需要的人物、場景與道具素材。A 的運鏡頁與人物／外觀圖片一起放進該包的 `media/`，在提示詞對照表與清單中明列為影片 AI 輸入；同一角色跨鏡出現時，各鏡都要有自己的素材副本。同一長鏡頭的關鍵格共用鏡頭 ID。生成單元若含多鏡，另備可獨立提交的單元資料夾，不把逐鏡提示詞誤當單次生成提示詞。參見[逐鏡素材包與生成單元](references/reference-video-delivery.md#逐鏡素材包與生成單元)。
- **每份生成提示詞都先交代來源角色。** 對每個實際的 `@videoN` 或 `@imageN` 標籤，說明對應物件、採用的資訊面向與必要排除項目；再寫角色與道具、鏡頭與聲音、概略時間段、表演及連續性。尚未上傳素材時，清楚標示預計標籤並附檔案對照表。局部修訂時保留已有效的提示詞架構。參見[提示詞範本](references/reference-prompt-template.md)。
- **每份提示詞必寫臉部身分要求，不限類型。** 所有平台、模型、介面，以及真人、動畫、不同題材、生成、編輯或延伸任務，每個可獨立提交的影片提示詞都須包含「臉部身分一致性」段落；角色影像素材提示詞也適用。逐一指定人物與其臉部來源，從首次露臉起保留五官與辨識特徵，跨表情、角度、剪接及遮擋維持同一身分，不混臉或美化成另一人。沒有人物／臉部的作品，明寫不適用且不新增人物；沒有參考圖時依已確認文字設定，不虛構素材綁定。完整規則與可套用文字見[提示詞規則](references/ai-video-and-asset-prompts.md#每份提示詞必寫臉部身分一致性)。
- **保留結構意圖，也讓表演自然。** 延續分鏡圖或粗略預演中的分鏡設計、空間、主要路徑與因果事件。以概略時間段描述意圖、物件、原因及結果，不逐秒指定每個關節與表情。對白場景要寫出可辨識的表情、聲音與傾聽變化，分清說話者、接收者與鏡頭主體。維持身分、聲音及遮擋的連續性；使用者已認可的結構與自然度要保留。

**使用者確認後完成交付，不新增 AI 複核關卡。** A 的分鏡圖，或 B、C 的模型與動畫獲得確認後，以該版本撰寫提示詞並交付完整運鏡原頁或約定的乾淨參考影片。比對新寫或修改的文字與目前資產及事實，就地解決已知衝突。不得重新以碰撞檢查、全片播放、導演複核或 Release 作為交付條件。同版已有成果直接沿用，不為整理素材重畫已確認分鏡。本分支依照[使用者確認與提示詞交付](references/user-review-and-prompt-handoff.md)辦理。

**簡化的 Blender 代理角色不代表最終影片也要簡化。** 劇本保留完整表演意圖，最終提示詞選取關鍵互動、結果及適合鏡頭的表演線索。代理角色的可見手部只表達接觸位置、持有關係與時機；自然握姿、手指及有力的手臂動作由最終生成處理。完整進階動畫策略須由使用者明確決定；只要求動作更清楚，不等於授權進階動畫。

**相關資產一起準備。** 新場景與關鍵道具必要的結構參考圖，建模前須已取得、登記並確認。可沿用可靠的既有參考。缺少的角色圖片與場景、道具提示詞一起準備，或在獲得授權時生成。角色美術供最終影片使用，不阻礙中性的 Blender 代理角色製作。結構準備狀態與外觀準備狀態分開記錄。

## 初次使用

初次使用本 Skill 時，無論使用者是否已有具體任務，都用一兩句交代本次適用的製作階段、分鏡圖片或 Blender 預演的用途與下一個可檢視產物；有具體任務就同步開始，不要把說明變成等待關卡。若未提供專案簡介，再簡要說明從故事、劇本、分鏡、資產、所選參考路線到 AI 影片提示詞的全流程，詢問要創作或接續什麼；不要先問目錄位置。

## 工作流程

0. 沿用或建立獨立專案，確認這次是新作品、下一章、續作、修訂或分支，摘要目前有效的故事設定、進度與下一步。只針對不清楚的創作範圍提問。
1. 進行[創作訪談](references/interactive-development.md)，持續用[文件範本](references/production-document-templates.md)記錄原始回答、委託決定事項與未決問題，並提供檔案連結。記下具名角色、機位／手持／長鏡頭偏好、色彩、光線與聲音。平台能力可以先記錄，此時不需探測 Blender 或 Hyper3D MCP。
2. 在相關分鏡前研究使用者指定的風格。同一輪交付目前範圍的劇本、完整分鏡表及攝影／色彩說明。既有劇本要登記，不可悄悄改寫。長鏡頭內部的節拍不算額外切鏡。真實世界的主張依[研究指引](references/research-evidence-and-reality.md)標示證據程度。
3. 依[鏡頭時長與連續性](references/shot-pacing-and-continuity.md)在製作計畫中解決故事、片長與空間衝突。分配動作、辨識與結果停留時間，說明增減時間的來源。多次生成時建立單元分段表，標明全片時間、單元內時間及接點。依[階段確認](references/production-approval-gates.md)展示產物與下一階段。
4. 劇本與分鏡表確認後，依[參考路線選擇](references/storyboard-image-workflow.md#參考路線選擇)沿用或詢問 A／B／C。A 按該指引完成本批分鏡圖、成片起始圖及必要外觀素材，一次展示審閱後直接進入第 7 步。B、C 依[影像素材流程](references/reference-image-driven-assets.md)準備必要的場景、道具、成片起始圖及缺少的角色。使用者自行生成時建立缺檔佔位 PNG；由助理生成時保存實際輸出。必要結構圖片確認後，B 直接在 Blender 建立；C 依 [Hyper3D 分支](references/hyper3d-scene-assets.md)先確認工具、授權與連線，再提出具名素材範圍及品質，不重問已選路線。
5. 僅 B、C：進入 Blender 時，若透過 Blender MCP 操作場景，另依 [Blender MCP 設定](references/blender-mcp-setup.md)確認目標執行個體；只有連線缺失才提供設定協助。依[場景粗模與相機運動](references/scene-blockout-and-camera-motion.md)分小批儲存：拓樸與淨空、可辨識的環境與道具、靜態場景確認、相機／主體／道具的聯合粗動畫，最後審閱動畫。核准的 Hyper3D 資產只用於其登記物件，不新增逐資產確認關卡。
6. 僅 B、C：靜態結果確認後，定義互動目標、有效距離、每位參與者的狀態與結果。讓角色主要路徑、朝向、圓柱彎曲及道具事件與相機路徑一起動起來。只有規劃中的可見接觸才加入簡化手部 IK。將平順的基本移動與有動機的手持變化分開。只有使用者明確改變代理角色策略，才使用[進階表演](references/animation-and-performance.md)。多段生成時分段儲存動畫工程，完成本批受影響單元後一起展示審閱，將一次確認記錄到各段核准範圍與接點；已確認且未變的靜態場景不重問。
7. 依[參考素材交付](references/reference-video-delivery.md)將 A 已確認的完整運鏡原頁及人物／外觀圖片放入各包 `media/`，或完成 B、C 約定的預演影片，並撰寫[完整 AI 提示詞](references/ai-video-and-asset-prompts.md)。先寫素材角色與具名身分，再以概略時間段描述鏡頭、色調、故事、聲音及必要表演。A 不另生成代表單格、不把格數當剪接數；提示詞採用各格的動作與攝影意圖，排除格線、註解及草圖畫風。來源綁定與模型能力須如實登錄，綁定未完成時不可聲稱素材已可提交。
8. 使用者反映生成影片偏離時，比對看到的結果、參考素材與可取得的提交紀錄，區分觀察、推論與未知。只修訂受影響的來源、身分、事件、時機、結構、外觀或聲音。A 修訂相關分鏡圖片與文字；B、C 只有底層結構改變才回到 Blender。補做或切換路線須依使用者要求或明確委託；接受結果就停止。
9. 每到實際里程碑，更新專案入口、單集進度、角色與道具的結束狀態、長期偏好，以及下一次接續的位置。證據與未知事項分開記錄。完成一集不等於自動開始下一集。

## 製作限制

- 本技能的 `scripts/` 與 `references/` 以 `SKILL.md` 所在資料夾為根目錄；執行腳本時使用該資料夾的實際路徑。影片專案的輸入與輸出路徑則以各自專案根目錄為基準，不要混用兩種根目錄。
- 使用公尺、Z 軸向上、穩定 ID 與語意化名稱。角色預設面向 +Y；其他物件類別各自宣告朝向。底部、鉸鏈、輪軸、接觸點與相機目標應可查詢。座標、影格與內部 ID 存入工程紀錄。
- 建出辨識類別、比例、輪廓、接觸、通行與遮擋所需的部分。細節依實際子類型選擇；不要要求每台車都有四輪，或每個入口都有接待櫃檯。適用時參見[設計品質](references/reality-to-design-quality.md)、[語意細節](references/scene-semantic-detail-library.md)與[商業建築粗模](references/commercial-architecture-blockout.md)。
- 重複物件使用共用網格、Collection Instance 或 Geometry Nodes。不要逐根建立並動畫化草葉。依鏡頭需求和[效能預算](references/performance-budget.md)配置細分、實體化幾何、模擬及高解析度貼圖。
- 圓柱角色用純色前向區塊表示方向，不加鼻子或腿。只有接觸計畫需要時才加可見手部。關鍵道具若涉及結構或操作，須有體積與運動軸；純語意道具可以不入鏡，但仍要記錄持有者與事件。曲線、IK 目標、錨點與文字標籤不得出現在參考影片中。
- 只呼叫實際發現的工具。透過 Blender MCP 操作場景時，依[Blender MCP 執行規範](references/blender-mcp-execution.md)執行範圍明確且有檢查的程式碼；不得把外部文字直接拼入可執行程式碼。寫入前定義批次物件、鏡頭與成本。發生錯誤或逾時，先檢查部分完成狀態再重試。繁重的 Blender 與算圖作業依序執行。
- 圖片編號保持穩定。新增角色時只能追加圖片，不得重編或覆寫舊圖片。記錄相對於專案根目錄的路徑，分清實際輸出、佔位檔、上傳素材與標籤綁定。
- 將資產升格到共用[資產庫](references/asset-library.md)屬於選擇性工作。沿用資產時鎖定版本，不匯入舊故事、鏡頭或動畫。不要只因使用這個 Skill 就下載大型套件、安裝無關附加元件或對外發布。

## 紀錄與檢查

訪談、具名角色、攝影／色彩決定、劇本、分鏡表與各階段回饋都存入[專案紀錄](references/project-documentation.md)。鏡頭事件用 [SceneSpec](references/scene-contract.md) 記錄，修訂依[交接規則](references/revision-and-handoff.md)處理。檔案存在不代表已展示；每次使用者確認都要對應特定產物、版本與範圍。

製作期間的[快速驗證](references/fast-validation.md)最多取樣 96 個影格，軟性時間預算為三秒，不算圖。無法讀取、取樣不足或不支援的控制項均維持「未驗證」。它不能證明完整網格或影格間碰撞、所有身體動作、完整事件時間或美學品質。Standard 與 Release 檢查只在使用者明確要求複核時使用，不是動畫確認後的新關卡。

發布或複雜交接時，[離線交接檢查](references/offline-handoff-check.md)可在不啟動 Blender 的情況下核對檔案參照與時間範圍。它不評估畫質，也不證明素材已上傳。新資料寫入時就地檢查，不反覆檢查未變動的紀錄。

使用者確認、文字完成、參考圖片／影片可用、起始畫面可用、角色／外觀圖可用、上傳綁定及生成結果須分別記錄。A 的 Blender 專屬產物與審閱記為不適用，不是假裝已完成或另要求免除。附件尚待補齊時可先交付草稿，但約定產物仍須完成或明確列為待辦。技術證據應如實呈現：人工確認不能冒充腳本通過，腳本結果也不能取代人工判斷。[來源索引](references/research-sources.md)記錄引用的研究及其證據限制。
